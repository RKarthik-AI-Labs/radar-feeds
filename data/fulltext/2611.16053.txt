Abstract

To act effectively, agents must gather contextual information across resources such as chats, issue trackers, email and knowledge bases, to answer questions like 
what was decided in the last project meeting?
 or 
where is the FAQ for our internal tooling?
 Where this information lives in a user’s environment is unknown to the agent, so it re-explores the same resources across consecutive interactions. Common routing approaches represent each resource as a tool and rely on high-level descriptions to generalize to unseen environments. Such descriptions often fail to separate similar or overlapping resources and cannot improve from the agent’s subsequent interactions. We introduce Wayfinder, an adaptive router that uses the documents cited by the downstream agent as feedback about where relevant information resides. These citations update Wayfinder’s internal resource representations, which subsequent interactions use to prioritize the resources likely to contain relevant information. We also introduce resource augmentation during offline reinforcement learning, which anonymizes and permutes resource identities to discourage training-time overfitting of which resource holds which topic; our ablations suggest it helps most when few training environments are available. Because no openly available professional environments pair realistic queries with resource-access patterns, we construct and release three controlled testbeds derived from existing datasets: NFCorpus, FEVER and Tech Startup. Compared with supervised, tool-retrieval and contextual bandit baselines under a shared closed-loop protocol, Wayfinder gives the best routing when resources contain semantically overlapping content that static descriptions cannot distinguish, while description-based tool retrieval suffices when resources are drawn from distinct corpora.

Introduction

Large Language Models (LLMs) are increasingly judged by their ability to act as agents to accomplish tasks on behalf of users 
[
5
, 
11
, 
30
]
. To complete tasks, however, an agent must do more than reason and act: it requires contextual information about the user’s environment. Answering 
what was decided in the last project meeting?
 or 
where do I look up the FAQ for internal LiteLLM?
 means seeking evidence across resources such as chats, issue trackers, email, or knowledge bases, each reachable only through a tool that retrieves the documents that specific resource contains (e.g., conversations, tickets, articles) 
[
1
, 
2
]
.
Where that grounding information resides is user- or organization-specific and is not known to the agent in advance: an ongoing project may be documented in chat threads in one organization, but captured in email conversations or issue tickets in another. This creates a gap between the agent’s prior knowledge and the target environment (i.e., the collection of available resources) in which it operates. Lacking that knowledge, the agent must rediscover the layout of the environment during every new user-agent interaction, re-exploring the same resources across consecutive interactions even after earlier ones revealed where some of that information is kept.

A natural response is to treat each resource together with its access tool as a distinct tool, which frames resource routing as tool selection problem. The distinction is that these tools while having a different resource name often have the same search functionality 
[resource_name].search(query)
docs
, and differ only in the documents behind them. Thus, any description used for selection must stand in for contents that cannot be enumerated ahead of deployment. The dominant approaches consume exactly such descriptions: an LLM ranks resources from them (ReSLLM 
[
34
]
), or a contrastively trained bi-encoder embeds them and scores them by similarity to the query (ToolRetriever 
[
26
]
). Both inherit the limits of the description: they cannot separate resources whose contents overlap semantically, and they are fixed at deployment, so what the agent discovers in one interaction cannot inform the next. Reinforcement learning has been applied to tool selection 
[
25
]
, but reward computation requires gold tool calls which are not available at deployment. Supervised routers such as Learn2Rank 
[
12
]
 and RouteRAG 
[
15
]
 share similar limitations requiring labeled queries of the target user’s environment but a newly encountered environment supplies neither. What remains missing is a routing method that can adapt to a target environment without labels from it.

User–agent interactions already supply a proxy for these labels: answering a query, the agent cites the documents it relied on, and those citations are grounded evidence of where the information a user needs resides in their environment. We introduce Wayfinder, an adaptive router that updates itself from those cited documents. Wayfinder maintains a bounded representation of each resource, which we call a 
resource sketch
, that subsequent interactions consult to prioritize the resources likely to contain the answer. Adaptation therefore happens online, without target-environment labels and without access to the resources’ full contents. Routing is advisory rather than restrictive: the agent remains free to search beyond the recommended resources, so the signal continues to arrive even when the router is wrong. The policy itself is trained offline with Reinforcement Learning 
[
27
]
 on training environments; to keep it from memorizing which resource names carry which topics rather than routing on evidence, we anonymize and permute resource identities during training. Our ablations indicate this augmentation matters most when a limited number of training environments is available.

We evaluate in controlled federated environments spanning intra-corpus partitions (NFCorpus, FEVER) and cross-corpus heterogeneity (Tech Startup), with every router run under the same closed-loop protocol. 1.

No access to target-environment supervision.

During training, the router is learned from a set of training environments and their associated queries, but the target environment and its queries are not available. This setting reflects practical deployments of agentic systems (e.g., Claude Cowork 
[
1

2.

Restricted resource access via tools.

Resources are accessible only through their corresponding tools or APIs, and their contents cannot be exhaustively enumerated or randomly sampled. Consequently, methods that assume full corpus access or centralized indexing across resources are not applicable in this setting.

These constraints define a learning problem in which routing decisions must be inferred under partial observability and weak supervision, distinguishing it from standard tool use settings where the tool description and functionality does not vary across environments (bash, calculator, git, etc.). Because the router must generalize from training environments to previously unseen target deployments, we refer to this routing problem as the 
Adaptive Agent Routing Problem
.

3 
Related Work

End-to-end RL-based RAG systems.

Recent work optimizes retrieval-augmented generation pipelines end-to-end with structured or verifiable rewards, jointly training query reformulation, retrieval, reranking, or knowledge-graph traversal 
[
8
, 
16
]
. These systems assume direct control over the retrieval stack. Wayfinder instead isolates the upstream problem of 
resource routing
, treats each resource as a black-box retriever, and acts as a parameter-efficient routing layer that can be composed with such pipelines rather than replacing them.

Resource selection and bandit routing.

Resource selection has a long history in distributed information retrieval and federated search 
[
28
, 
4
]
. Classical methods like CORI 
[
7
]
 use term statistics with no learning. Supervised approaches 
[
15
, 
12
, 
17
, 
9
]
 learn classifiers or rankers from labeled query–resource pairs and perform well in data-rich, stationary deployments, but assume stable resource semantics and degrade under distribution shift or in low-data target environments. A complementary line formulates routing as a bandit problem with online reward attribution 
[
3
, 
14
]
. In agentic settings, however, feedback is sparse, trajectory-level, and mediated by multi-step tool use, complicating per-arm credit assignment, and standard bandit formulations maintain only compact per-arm statistics rather than structured interaction context.

Tool retrieval and zero-shot tool generalization.

Treating each resource together with its access tool as a distinct tool makes our action space formally an instance of tool selection with the key distinction that descriptions, when used, have to reflect the content of the resources as the functionality and signature are largely the same across tools (to retrieve documents and 
search(query)
docs
). ReSLLM 
[
34
]
 is a method that uses a description of the resource contents to describe the tool which an LLM (used as the router) uses to rank the tools. On the other hand dense-retrieval variants like ToolRetriever 
[
26
]
 embeds the same descriptions with a contrastively trained bi-encoder and scores them by similarity to the query .

Reinforcement learning has also been applied to tool selection 
[
25
]
, with the reward computed by matching the predicted call against a gold tool call. Learning therefore requires labeled data for these tools. A newly encountered target environment, with a new distribution of resources, carries no such annotation: no query is labelled with the resource that holds its answer. Wayfinder instead rewards a routing decision using the documents the primary agent cites while answering requiring no labelled data of the target environment.

Memory-augmented agents.

Long-term memory systems for LLMs (MemoryLLM 
[
35
]
, M+ 
[
36
]
, MemGPT 
[
24
]
) and agentic continual-learning systems such as CLIN 
[
23
]
 compress past interactions to retain content or user preferences. These approaches target 
content retention
 rather than the 
navigational
 problem of identifying which external resources are likely to be useful for a query.

What separates Wayfinder from the work above is its supervision, not its components. Most routers discussed decide from evidence fixed before deployment: a resource description (ReSLLM, ToolRetriever), corpus statistics over enumerated contents (CORI, ReDDE), or labelled query–resource pairs from the target environment (Learn2Rank, RouteRAG). Wayfinder instead uses the agent’s citations to adapt to the target environment and become more efficient as the user interacts more with the agent.

Methodology: Wayfinder

When we open a new agent session and ask it to perform an action or answer a question the agent often needs to explore the environment to gather context, learning along the way where the information that is relevant to that user is kept. This knowledge is lost when the session ends, and the next session has to repeat the same exploration. We argue that this is inefficient. Queries about the same project tend to be answered from the same few resources, so earlier sessions can inform later ones. Citations also point at evidence the agent actually used to answer a question. Wayfinder builds upon this observation and proposes a citation-gating mechanism to retain and utilize this knowledge across sessions.

4.4 
Forcing the policy to read evidence, not identifiers

A policy trained on a small number of environments can memorize which identifier carries which topic (“coding questions go to resource A”). The shortcut scores well in training and collapses in a target environment for which resources may carry different content, so it has to be prevented during training rather than detected afterwards. We therefore apply two augmentations while training the policy, both at the granularity of a 
session
: a single training rollout, within which one assignment of identifiers to resources is held fixed.

Resource encoding.
 Descriptive names (“email”, “chat”) are replaced by anonymous identifiers 
 in both the input and the action vocabulary, removing name-based priors.

Resource randomization.
 Each rollout draws a fresh permutation mapping resources to identifiers, applied consistently within that rollout.

Together the two leave no stable association between an identifier and a topic across query rollouts. Sketch content is then the only signal that survives from one rollout to the next, which is the signal that the policy must learn to interpret.

7.1 
Experiment 1: Routers Comparison

Our hypothesis is
that citation-derived adaptation pays in proportion to how poorly static descriptions separate
resources. On the intra-corpus benchmarks, roughly fifty resources are drawn from a single

Limitations and future work

Wayfinder depends on the primary agent’s citations. Missing citations slow adaptation, but incorrect ones write wrong evidence into the resource sketches, and routing degrades as their rate grows (Appendix 
F.2
); weighting updates by citation confidence, decaying unconfirmed evidence, or revising a sketch when later citations contradict it could limit this, and we leave their evaluation to future work. Our benchmarks are controlled testbeds built from public corpora, so they do not capture enterprise permission structures or production-scale latency. Evaluating Wayfinder with authentic tools and users is the natural next step.

Appendix A 
Robustness to Non-Stationarity

Non-stationarity is a defining characteristic of federated environments, where the information within resources can change over time independently of the agent’s actions.
To evaluate robustness to such exogenous changes, we progressively relocate an increasing fraction of ground-truth documents associated with test queries to different resources before testing, simulating changes in where information resides after deployment.
Higher drift levels subsume lower ones to ensure consistency across settings, and all methods are evaluated under identical drift realizations to isolate differences in routing behavior.
We report routing recall and precision to assess how effectively each method maintains routing quality as the environment diverges from the training distribution.

Figure

However, Wayfinder maintains higher recall and precision across all drift levels, indicating greater robustness to changes in where relevant information resides.

These results suggest that learning routing policies from interaction feedback yields representations that are less tightly coupled to specific resource assignments, improving resilience to post-deployment environmental changes.

Appendix C 
Appendix: Data Construction Process

We construct synthetic federated retrieval environments from BEIR benchmarks to enable controlled evaluation of routing under non-stationarity. Starting from a standard BEIR dataset (corpus, queries, and relevance judgments), we transform static collections into dynamic, multi-resource environments with temporal structure and exogenous drift.

For datasets with graded relevance (e.g., NFCorpus), we retain only highly relevant documents and normalize relevance to binary. Queries without relevant documents after filtering are removed to ensure well-defined routing supervision.

Each dataset is partitioned into multiple independent environments, representing distinct information spaces. Documents are disjointly assigned to environments. Within each environment, documents are organized into a fixed number of resources. Resources are constructed by clustering document embeddings (using a sentence transformer) via a Gaussian Mixture Model, ensuring semantic coherence within each resource and mimic similar content across resources.

To support description-based baselines, each resource is associated with an automatically generated natural-language description. Descriptions are produced by prompting a large language model with representative document samples from the resource (100).

Within each environment, queries are temporally ordered in a query stream to form a single timeline, simulating interactions in a shared environment.

Queries are split temporally into training and test segments using an 80/20 ratio. When enabled, exogenous drift events are realized by randomly moving documents across resources. Drifts are applied only during the test period and preferentially target ground-truth relevant documents to mimic meaningful drifts. Drift is introduced incrementally at multiple rates, where higher drift levels subsume lower ones.

Before drift, we compute ground-truth coverage statistics per environment to characterize task difficulty. The final dataset includes the initial resource state, persona query streams, relevance judgments, train–test splits, pre-computed embeddings, and drift event specifications. All stochastic components are seed-controlled to ensure reproducibility.

This construction enables systematic evaluation of routing policies under controlled resource fragmentation, partial observability, and increasing degrees of non-stationarity.

The mem0 baseline stores past query–resource trajectories as text, embeds them with a sentence-transformer model, and retrieves semantically similar trajectories by vector similarity; candidate resources are then extracted from the retrieved trajectories. Wayfinder’s memory instead represents resources as persistent entities and records interaction outcomes per resource, enabling reasoning about resource-specific reliability over time. Both variants share the same base model, resource representations, routing budget, and training procedure; only the memory structure differs.
