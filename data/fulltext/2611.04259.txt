Abstract.

Larger generative retrieval models can improve retrieval quality, but their decoding cost makes low-latency serving difficult. When different users submit the same query, generating complete Semantic IDs (SIDs) for every request repeats computation, while their interaction histories call for different results. The challenge is to reuse large-model computation across requests while keeping retrieval personalized.

We propose 
ReuseGR
, which separates query-level candidate planning from request-level personalized completion. A 7B offline planner generates SID prefix sets shared across requests with the same query. A 0.5B online model uses each request’s history to select prefixes and generate the remaining tokens. ReuseCut chooses a cache depth for each query based on historical coverage, balancing computation reuse and candidate coverage. To strengthen online completion, we transfer 7B suffix-scoring knowledge to 0.5B through path-level knowledge distillation (Path KD). BudgetCut then selects scored branches to improve final top-100 recall under a fixed branch budget. Its selection policy is initialized by on-policy distillation (OPD) and refined through group-relative policy optimization (GRPO).

On an industrial search-advertising dataset with approximately 2M query–item records and 3.38M catalog items, ReuseGR improves query-level HR@100 by 3.83 percentage points and reduces mean online latency by 38.9% relative to an all-online 0.5B baseline when prefixes are prepared. It achieves HR@100 comparable to an all-online 7B baseline with 57.7% lower online latency. A 14-day user-level online A/B test against the 0.5B baseline shows relative gains of 0.93% in click-through rate and 1.05% in revenue per thousand requests.

Generative retrieval, Semantic ID, Personalized search, Adaptive prefix caching, Knowledge distillation, Sponsored search

Introduction

Search-advertising systems select candidates from million-item catalogs
for downstream ranking, making candidate quality central to user experience
and advertising value. Traditional retrieval matches queries
against indexed item representations 
(
Huang et al., 2013
; 
Karpukhin et al., 2020
)
.
Generative retrieval learns to predict candidate identifiers directly,
allowing semantic knowledge in the model to guide candidate
selection 
(
Tay et al., 2022
; 
Wang et al., 2022
)
.
Semantic IDs (SIDs) represent items as short token sequences whose prefixes
group related items 
(
Rajput et al., 2023
)
. This structure lets a
generator select candidates through successive token predictions.
As illustrated in the upper half of Figure

, the model
reads a query and user history, then decodes complete SIDs one token at a time.

Larger generators improve retrieval quality but increase online decoding
cost. Existing methods address this cost in several ways: distillation
teaches a smaller decoder or lightweight prediction heads to imitate a
large teacher, reducing computation per prediction 
(
Zhang et al., 2026
; 
Guo et al., 2026
)
;
parallel prediction produces SID tokens in the same model call instead
of waiting for each preceding token, reducing sequential computation 
(
Hou et al., 2025
)
; speculative decoding lets a small model draft
candidate sequences for batched verification by a large
model 
(
Lin et al., 2025
)
; prompt caching reuses attention states for
shared input blocks, such as history and item representations, reducing
repeated context processing 
(
Zhao et al., 2026
)
.
These approaches lower the cost of online prediction, while candidate
SIDs are still generated for each search. Repeated queries offer another
source of savings: sharing large-model planning across users.

We ask whether part of this planning can be performed offline and reused
by users who submit the same query. The upper half of
Figure 
1(a)
 makes the opportunity concrete: two histories
lead to different complete SIDs, yet their shared initial tokens are
recomputed for both searches. Our idea is to cache query-dependent SID
prefixes and let the current history guide their completion online.
Each prefix preserves a subtree with multiple continuations, so the
online model can generate candidates beyond a precomputed list of
complete SIDs. This would share expensive planning while keeping final
candidate selection responsive to the user.

Our click-log analysis examines the feasibility of this idea and the
choice of prefix length. When predicting the next SID token at matched
preceding prefixes, query information contributes much more at the first
two layers than at later layers (Figure 
3
). This supports
sharing coarse candidate structure across users. The suitable sharing
boundary also varies by query: model-generated prefix sets at
query-specific depths retain 78.62% of target
SIDs on average, versus 74.18% at a uniform
two-token depth under the same prefix-count limit. These are reachable
target fractions before online completion. A deeper cut saves decoding
steps but narrows the available subtrees; a shallower cut leaves more
choices for history-conditioned generation. The design must therefore
identify reusable prefixes and select how far each query can reuse them.

We implement this design as 
ReuseGR
. In the lower half of
Figure 
1(a)
, query 
 reuses one token and 
 reuses
three; users searching for either query share its prefixes while their
histories guide different suffixes. ReuseCut predicts these depths from
query text using historical target-coverage labels. A 7B offline planner
produces the shared prefix sets, and a 0.5B online model completes them
using the current query and history. To guide the small model’s suffix
scoring with large-model knowledge, we apply path-level knowledge
distillation (Path KD) from the 7B teacher. After scoring, branches are
merged to form the final retrieval results, so branch selection affects
which relevant SIDs enter the top-100 ranking. We develop BudgetCut to
learn this selection under a fixed branch budget. On-policy distillation
(OPD) initializes its policy from marginal recall gains, and group-relative
policy optimization (GRPO) refines the policy using the recall of complete
selected branch sets.

On AE-PV, an industrial search-advertising dataset with 3.38M items and
44,225 Test queries, ReuseGR achieves 85.82% query-level
HR@100 and 46.05% Recall@100 at
71.45 ms mean online latency with prepared prefixes.
It gains 3.83 HR@100 points and reduces latency by 38.9% over an
all-online 0.5B baseline, with HR@100 comparable to all-online 7B at
57.7% lower latency (Figure 
1(b)
). Matching depths to
queries improves HR@100 by 3.17 points over permuted assignments with
the same depth distribution. With actual request histories, completion
recovers clicked SIDs outside the query-only 7B top-100 list on 5.67%
of rows. A 14-day user-level online A/B test against 0.5B end-to-end
retrieval yields relative gains of 0.93% in click-through rate and
1.05% in revenue per thousand requests.

In summary, our key contributions are threefold:

First, we identify shared SID-prefix structure and
query-dependent reuse boundaries in click logs, providing an empirical
basis for sharing large-model candidate planning across users while
retaining history-conditioned completion.

Second, we develop ReuseGR to connect 7B offline planning with
0.5B online personalized retrieval through adaptive prefix-depth
selection, suffix-score distillation, and set-dependent branch admission.

Third, we validate query–depth matching and personalized
completion through controlled experiments and comparisons with
complete-result caching and reranking, and demonstrate the system’s
retrieval quality, serving efficiency, and business value on industrial
data and in a 14-day online A/B test.

4.1. 
System Overview

ReuseGR separates shared candidate planning from personalized completion
(Figure 
2
). Offline, a 7B model generates SID prefixes at
a depth selected for each query. Online, a 0.5B model expands these
prefixes using the current query and history; BudgetCut selects scored
branches for the final ranking. Cold misses use a separate 0.5B end-to-end (E2E) model.

5.7. 
Online Evaluation (RQ6)

We conducted a 14-day online A/B test on a leading global e-commerce platform serving hundreds of millions of users.

ReuseGR replaces the 0.5B E2E retriever. ReuseCut
selects a cache depth per query, and the 7B planner stores SID prefixes
and scores. Prepared queries use the current history to complete cached
prefixes or the depth-zero root; BudgetCut filters branches before top-100 SID
ranking and item expansion.

Request serving and cache maintenance run separately. A cache miss
immediately uses the original 0.5B E2E model to decode all four SID layers
with the current context. Missed queries with positive predicted depth
enter a deduplicated, rate-limited queue for asynchronous 7B planning.
Published entries serve later requests; periodic refresh limits staleness.
Depth-zero misses remain fully online without backfill. Requests therefore
never wait for 7B planning, and both hit and miss paths retain current
user context.

A 14-day user-level A/B test assigned 10% traffic per arm in production
search advertising. Other retrieval channels, quotas, ranking, and
bidding were unchanged. From pooled counts, CTR (clicks/impressions) and
RPM (revenue per 1,000 requests) rose 0.93% and 1.05% relative to
baseline. Orders per request rose 0.78%; CVR (orders/clicks) fell 0.21%.
SID-tagged impression/click shares rose 3.00/4.70 percentage points; the
share of requests with a SID-tagged impression rose 5.36 points. These
shares measure channel participation with potentially overlapping tags.

6. 
Conclusion

ReuseGR combines 7B offline query-prefix planning with 0.5B online
history-conditioned completion, using ReuseCut for adaptive depth,
Path KD for suffix scoring, and BudgetCut for branch admission. Adaptive prefix reuse balances retrieval quality and efficiency.
On AE-PV’s 3.38M-item catalog,
ReuseGR achieves 85.82% HR@100 and 46.05% Recall@100 at 71.45 ms with
available prefix entries: 38.9% lower latency than 0.5B e2e and comparable
HR@100 to 7B e2e. Query-level prefix reuse shares computation across
requests, while each request’s history guides candidate selection within
the cached subtrees.
A 14-day online A/B test yields relative CTR and RPM gains of 0.93% and
1.05% over the 0.5B e2e baseline.
