Abstract

A scientific agent can give the same verdict while reading and citing different evidence. BioAgent-DF tests this separation using paired reference and candidate values saved at the same scientific computation site. It restores or transplants those values at their original coordinates, then runs the agent on healthy hardware. Across eight SciFact batches, Qwen3.5-4B shows repeatable citation changes in three capture–claim combinations, and Gemma 3 4B IT shows repeatable read and citation changes in four. These seven combinations cover two claims. Full restoration recovers the reference evidence sets while verdicts remain unchanged. Verdict changes observed under the baseline prompt did not recur under the explicit-example prompt. Complementary tool and optimizer experiments distinguish recovery of numerical state, recovery of ranked lists, and restoration of an agent’s visible history. These results show that an audit should track both the evidence an agent uses and its final answer. In hERG cardiac-safety assay allocation, silent numerical faults changed testing decisions while the fixed-budget shortlist kept the same number of compounds labeled as blockers. After the agent had used faulty values, restoring its earlier execution state and supplying certified scores recovered all 39 changed decisions, whereas replacing the prediction file recovered none; no incorrect action was committed. A streaming implementation of the arithmetic checks reduced the total time for forward execution and verification by 42.4% relative to the original FP64 implementation, with identical flags and recovery outputs.

1 
Introduction

Biomedical research agents retrieve literature, inspect molecular and cellular features, and choose what to examine next. The final verdict captures only one part of this process. Two executions can agree on a claim while selecting different documents or citing different sentences. We ask whether silently corrupted tool values change those evidence choices, and how much of the tool’s output must be restored to undo the change.

Evidence-path fidelity means agreement with a specified reference execution in recorded retrieval, read, and citation endpoints. Scientific decision fidelity (the DF in BioAgent-DF) is the broader audit, covering actions, item selection, and verdicts as well.

We investigate silent data corruption (SDC) observed on faulty GPUs during distributed training and its downstream effects on scientific agents. Finite, erroneous outputs can pass ordinary NaN/Inf monitoring and reach a tool result. The faulty GPUs fall into two classes: 
Case 1 (size-dependent)
 GPUs fail more often on tested large-matrix paths than on short probes; 
Case 2 (expanded-trigger)
 GPUs also fail on those short probes.

BioAgent-DF uses controlled tool-state interventions to trace and restore biomedical agents’ recorded evidence paths (Figure 
1

The experiments test the numerical validity of the paired values, their effect on recorded reads and reported citations, and the replacements that recover reference endpoints under matched continuation conditions (Appendices A–H).

We also test whether numerical errors redirect measurements on prespecified screening inputs and alter hERG assay allocation. Restoring reference values at their original coordinates identifies values responsible for changed actions; selective recomputation repairs decisions, and certification determines when they can authorize action under a fixed computation contract. The hERG experiment compares replacing the prediction file with restoring the execution state after the agent has used faulty values (Appendices

5.3 
Agent behavior and certified commitment

All 36 Case 2 hERG trajectories whose inputs changed a decision followed the supplied decision rule (Appendix 
I.2

Each context paired a screening input with a target: molecular solubility or a cell surface marker (CD3 or CD14). Forty contexts with repeatable behavioral differences between reference and candidate inputs were evaluated four times per condition. With the shortlist produced by reference computation held fixed, candidate numerical fields changed the set of objects chosen for measurement in 76 of 160 trajectories relative to reference values (Appendix

Algorithm 3. Certified commitment.
 Hold tool outputs during independent arithmetic verification. On trusted hardware, recompute flagged predictions and scores whose decisions remain unresolved under valid bounds; re-rank the full candidate set until the target and every returned value are certified. If the agent consumed a replaced output, restore its visible history, discard dependent state and pending actions, and invalidate server-side state built from the discarded history or on untrusted hardware, such as key–value caches. A certificate records the certified decision and supporting evidence. A commit service checks action agreement with the current certificate for the same request and contract, then commits at most once per request. If verification fails or the budget is exhausted, recompute every score on trusted hardware or commit nothing.

5.4 
Recovery and commitment for each request

In native Biomni, we implemented the fallback of Algorithm 3 that recomputes every score on trusted hardware. It restores the execution state when needed and uses a commit service that accepts only actions agreeing with the current certificate. The 16 confirmation fault sources and one shared healthy reference, each evaluated on two tasks with three repeats, gave 102 requests, each run under three recovery conditions (Appendix 
I.7
). Arithmetic verification flagged all 16 faulty sources and not the healthy reference. Certification used full trusted recomputation in all three recovery conditions. Recovery before the agent read the predictions gave the healthy decision in all 102 requests. After the agent had read the faulty predictions, replacing the prediction file recovered none of the 39 changed decisions, whereas restoring the execution state saved before that read and continuing with recomputed scores recovered all 39 and preserved the other 63. No wrong action was committed. For SciFact citations, joint restoration of history and tool state likewise returned discordance to the level observed in a healthy repeat.

On a healthy data-center GPU, a streaming implementation of the same checks raised a 0.47 s forward pass to 0.59 s, compared with 1.02 s for the original FP64 implementation and 0.88 s for double execution, which repeats the forward pass and compares outputs (Appendix 
I.4
). Across the 96 requests with faulty inputs, continuation from the restored state added about 29,000 tokens per request to the 44,000 already spent analyzing the faulty predictions; recovery before reading needed one analysis of about 44,000 tokens (Appendix 
I.7
).

7 
Discussion and conclusion

The repeatedly confirmed SciFact result is a separation between verdict and evidence path. Numerical diagnostics separate arithmetic anomalies from the ordinary precision effects that also change membership between healthy references. Original-coordinate interventions test which value differences matter: full restoration returned the reference reads and citations in every confirmed case, while no tested partial-row mask both restored the reference path and reproduced the candidate path. For claim 831, the mask selects 8 of 38 global row blocks but replaces every changed score in the visited row, making it a full-row replacement despite its global sparsity.

The repeatedly confirmed evidence-path changes span two claims and two 4B models in Case 2 captures selected for upstream retrieval changes; without that selection, candidate values cause no more discordance than a healthy repeat (Table 
2
). Because the eight batches repeat identical temperature-zero requests, the independent units are captures and claims, compared over jointly completed groups. Stable verdicts can conceal changed evidence paths, so audits should record what an agent reads and cites alongside its verdict.

In hERG assay allocation, decision changes reflected score displacements relative to decision boundaries, including movement of the selection boundary when competing scores changed.

When a research agent directs experiments in an automated laboratory 
[
64
, 
65
]
, a numerical fault that changes its decision changes the experiment performed. Aggregate measures need not reveal such changes: in hERG assay allocation, the shortlist kept the same number of labeled blockers while the compounds assigned to testing changed. Verification therefore belongs where a decision is committed: flagged and unresolved scores are recomputed on trusted hardware, an agent that has used superseded values resumes from the execution state saved before it read them, and only certified decisions are committed. In our experiments, the check preceded the commitment of an assay allocation; in an automated laboratory, it would precede the instructions sent to instruments.

We propose extending this framework to decision recovery under a shared budget for computation, agent execution and experimental measurements. A recovery agent would choose which calculations to verify or repeat, which dependent execution state to restore and which measurements to acquire, aiming to resolve as many pending decisions as possible. Valid error bounds or trusted recomputation would support certification of decision agreement with a specified reference computation; new measurements would provide evidence for resolving the underlying biological question under prespecified experimental criteria.

A benchmark with evaluation references hidden from the agent would separately score fault detection, acquisition of trusted evidence, recovery of reference decisions, evidence-based revision and correct commitment. Prospective studies in automated laboratories, with independent measurements and replication across sites, would measure missed or spurious findings, experimental resource use and recovery cost. In that setting, scientific decision fidelity concerns which experiments are performed, not only which conclusions are reported.

Deterministic settings do not eliminate these anomalies. Retaining BF16 inputs while computing in FP32 produces identical results across comparison groups. FP16 errors occur on some tested paths; the FFMA, TensorFloat-32 (TF32), integer multiply-add (IMAD), and INT8 controls show no anomaly. INT4 and bit matrix multiply-accumulate (BMMA) were not fully evaluated.
