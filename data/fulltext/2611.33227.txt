Abstract

Language models can generate Python that drives industrial protocols on
programmable logic controllers, yet existing code-grounding checks ask whether
an imported package or symbol exists rather than whether it suits the declared
industrial target. We define 
metadata-conditioned, import-level
vendor–protocol incompatibility
 and build 
Proteus-OT
, a label-free
static verifier over a version-pinned graph of documented bindings. Across 883
generated scripts, 180 carry an import-level mismatch against the declared
target (20.4%); restricting to
single-vendor targets gives 16.3%, and additionally requiring the offending
library to reach a protocol communication call gives
14.2%, which we read as conditional on the corpus
metadata rather than on verified intent. None of the 28 adjudicable human
control files carries one, a sample too small to estimate a prevalence. Within
the balanced subset, 96.6% of mismatching scripts
import packages and call methods that exist, so an existence baseline does not
represent them, and every positive ships with an inspectable witness. We also
audit machine-versus-human classification on the same corpus, where character

-grams reach macro-F1 1.000 under task, model and vendor-disjoint
partitions and survive comment removal, an AST round trip and identifier
anonymisation. The trailing newline present in 95.2% of human files and in none
of the generated ones separates the classes on its own. Vendor–protocol
consistency is a useful static audit target, whereas provenance classification
on repository-labelled corpora is not authorship detection.

Index Terms: 
industrial control systems, operational technology security, large language
models, static analysis, dataset artifacts, programmable logic controllers.

I 
Introduction

Programmable logic controllers sit where computation meets physical process,
which is why they have been decisive in the most consequential intrusions on
record 
[
2
, 
3
]
. Mounting such an operation has
historically demanded process knowledge, vendor-specific protocol familiarity
and time with real hardware. Cook et al. 
[
1
]
 report that
general-purpose language models supply part of that combination, generating PLC
attack scripts from prompts and validating them against live controllers, so
model assistance may lower the barrier to entry.

We ask the defensive question of whether such code can be checked in a form an
engineer can act on. Existing tooling reasons about token style or package
existence 
[
9
]
, and neither engages with what makes an
operational-technology (OT) script wrong. Industrial libraries are
vendor-bound, so 
snap7
 speaks Siemens’ S7comm and 
pycomm3
 speaks
Rockwell’s EtherNet/IP–CIP, yet a model prompted for a Schneider Modicon device
will often import one of them regardless, producing code that parses and calls
real methods while the documented bindings do not list that package for the
declared target. Existence checkers confirm the package and the symbol, then
stop. The gap we address is the
absence, across the venues we surveyed, of any static, pre-execution analysis
that reasons about the vendor–protocol suitability of the attack script itself
rather than about style, package existence, or run-time network behaviour.

We formalise this problem as a metadata-conditioned, import-level
incompatibility and build 
Proteus-OT
 around it, a static and label-free
auditor for operational-technology scripts that pairs a typed graph of public
bindings carrying per-edge sources with a verifier emitting a twelve-component
readable vector, where every positive carries an inspectable witness. We also
examined whether the same grounded features help a machine-versus-human
classifier separate the two provenance classes. That earlier experiment reported
a 4.2 macro-
 point improvement, which we now retract, because the
component meant to flag hallucinated packages was firing on intra-repository
sibling imports and so keyed on repository structure rather than authorship. More
fundamentally, provenance classification proves degenerate on corpora of this
construction, and we report the corrected, non-significant gap together with the
artifact analysis that explains it, since an improvement over a defective
baseline is not a contribution.

This paper makes four contributions.

•

We define a metadata-conditioned, import-level vendor–protocol mismatch
predicate over a version-pinned binding graph, decidable from source with no
labels or trained model, where every positive carries an inspectable witness.

•

We audit 883 machine-generated scripts, reporting a 14.2% use-level rate
against a 20.4% inclusive upper bound, with 96.6% of flagged scripts falling
outside the evaluated existence baseline.

•

We show that machine-versus-human provenance classification on
repository-labelled corpora separates the classes by
construction rather than authorship, and reduce the confound to a single serialisation byte.

•

We bound recall by graph coverage and evasion by measurement, and release
the binding graph, evidence table, adjudication worksheet, splits, environment
and pipeline.

III-D
 
Witness Depth

Imports are not functional dependencies, so each positive is classified by how
deeply the script uses the offending library. With alias tracking
(
import lib as x
, 
from lib import X
) and one level of
assignment binding, we assign L0 when the alias is never referenced, L1 when it
is referenced but nothing is called, L2 when a library attribute is called, and
L3 when a call reaches a symbol on the protocol communication allowlist
(
connect
, 
db_read
, 
read_holding_registers
 and so
on), directly or through an object constructed from the library, which is the
strongest static evidence short of execution that the library sits on the
communication path.

IV-B
 
The Existence Baseline

The existence baseline flags a script if an imported top-level package is absent
from the pinned registry, or a called attribute is absent from the introspected
symbol table of an imported OT library. Within the balanced corpus, 29 of 168
machine scripts carry an OT-semantic flag, and the baseline is silent on 28 and
fires on 1, plus 4 scripts with no OT-semantic flag, so 96.6% [82.8, 99.4] are
not represented by it. The claim concerns the evaluated baseline rather than
every conceivable existence-based tool, since adding vendor–protocol edges would
make a tool no longer existence-based.

IV-E
 
Evasion and Graph Coverage

We bound the verifier’s scope by measurement rather than assertion, applying
seven source transformations to the 180 positives and reporting retention over
the applicable, still-parsing subset. Alias renaming, conditional import,
function-scoped import and a misleading vendor comment each retain 100%
detection, whereas dynamic 
__import__
, 
importlib
 and a
wrapper module each retain 0%. The first group is within scope, and the second
defines what the method does not cover. The comment decoy fails because the
target is path-derived, which is both a strength against text manipulation and
the source of the metadata dependence noted earlier.

Recall is bounded by the binding table, which covers 7 of 24 mainstream Python OT
packages and leaves

verified pass. All five vendor-lock edges carry a documented source.
Modbus-TCP is treated as vendor-neutral and never yields a witness, and a
protocol can be vendor-neutral while a device-family, function-code or
register-map assumption remains invalid, so vendor identity is a necessary but
not sufficient compatibility check.

V 
Discussion

Two of the three claims survive scrutiny, since under the encoded bindings and
the corpus metadata roughly one machine-generated script in seven uses a library
not documented as supporting its declared target, with that library on the
communication path, and most such scripts lie outside an existence baseline, all
computed without labels or a trained model.

The third does not survive, because the provenance classifier’s accuracy, and
the improvement attributed to grounding, cannot be read as authorship detection.
The construction is standard, with generated code from one collection and human
code from public repositories labelled by origin, yet the collections differ in
ways unrelated to authorship, since the human class is 75% library and test
code set against entirely standalone scripts and the serialisation differed, so
a single byte suffices. Both confounds are invisible to usual reporting, and
work reporting macro-
 0.98 under stratified cross-validation with
leave-one-model-out as a robustness check would pass review while measuring
nothing about authorship, as our own leave-one-model-out figure of 1.000 for
character 
-grams shows. This is the code analogue of hypothesis-only baselines
in natural-language inference 
[
22
]
, within the pattern
documented for security machine learning

The audit rests on metadata and partial coverage, which bound its claims. Target
vendors come from file naming, defensible metadata rather than verified intent, so
the rate depends on that channel and 44 flagged scripts name multiple vendors. We
release a blind
two-rater worksheet over all positives and 40 sampled negatives, and the
adjudicated rate remains future work, while only 28 of 190 human files are
adjudicable, so a matched corpus of human-written standalone OT scripts is the
binding constraint on any prevalence comparison. The verifier is as complete as
its bindings, exercises one context, checks vendor identity as a necessary but
not sufficient condition, and addresses an error made by a non-adversarial
generator rather than an adversary who has read this paper. It establishes
neither safety nor maliciousness, so deployment statements are feasibility
claims, and the earlier operating-cost argument for interpretability remains a
hypothesis until review cost is measured with analysts. On dual use, the bindings
are public and our contribution is their organisation, though we decline the
earlier assertion that an adversary gains nothing, since a mismatch checker can
also remove mismatches before deployment. We judge publication net-positive and
release the graph, evidence table, worksheet, splits, environment and pipeline,
but no executable attack scripts or live-controller tooling.

VI 
Conclusion

Proteus-OT
 decides metadata-conditioned, import-level vendor–protocol
incompatibility from source text and a documented binding table, without labels
or a trained model. The mismatch appears in 14.2% of machine-generated scripts
in this corpus when the target is unambiguous and the offending library reaches a
communication call, rising to 20.4% under the inclusive definition, and in none
of the 28 adjudicable human controls, with each positive carrying an inspectable
witness. On the same corpus, provenance classification separates machine from
human code almost perfectly but by construction rather than by authorship, with a
trailing byte alone sufficing, so accuracies reported for generated-code
detection on repository-labelled corpora reflect corpus construction and call for
the artifact audit demonstrated here. Where a domain supplies hard documented
constraints, grounding a check in them yields a decision reproducible by
construction. Future work should adjudicate the positives, broaden the graph
beyond its 7-of-24 coverage, exercise conditional context, and build the matched,
identically-serialised control corpus the provenance question requires.
