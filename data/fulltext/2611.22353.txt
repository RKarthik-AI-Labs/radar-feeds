Abstract

Dense retrieval is central to modern search, question answering, and retrieval-augmented generation, where high similarity is often treated as evidence of semantic relevance. We examine how far this assumption can be stressed. NONSENSE is a black-box sparse-edit probe that constructs visibly non-semantic strings while forbidding query-term copying, optimizing only the dense similarity between a query and the string. Across five BEIR-style datasets and three popular single-vector retrievers, these strings frequently outscore the retriever’s own best judged query-relevant passage (QRP), and often rank first in the full corpus. The result indicates a semanticity gap in the evaluated dense retrievers: nearest-neighbor status can be separated from passage-like meaning. These findings highlight the importance of evaluating dense retrievers not only by whether they retrieve relevant documents, but also by how reliably their similarity scores reflect semantic evidence.

1 
Introduction

Dense retrieval is now standard infrastructure for open-domain question answering and retrieval-augmented generation 
(
Karpukhin et al., 2020
; 
Lewis et al., 2020
; 
Petroni et al., 2021
)
. A common operational assumption follows: a highly ranked dense neighbor is at least passage-like evidence, even if it is not the best evidence. This paper tests that assumption directly. We ask whether a dense retriever can rank a visibly non-semantic string above the best judged query-relevant passage for the same query.

We introduce 
NONSENSE: 
Non
-Semantic Strings Expose 
S
emanticity Gaps in D
ense
 Retrieval
, a diagnostic probe for single-vector dense retrieval. Given a query and retriever, it initializes a fixed-length visible filler string and proposes one-character replacements. It accepts a replacement only when the candidate’s dense similarity to the query improves, rejects candidates containing query terms, and finally inserts the optimized string into the full corpus for ranking. The output is not a prompt injection, a hidden Unicode trick, or a query-term-repetition passage: it is an overt, non-semantic character string. Figure 
1
 illustrates the failure mode with examples of queries.

The main comparison is deliberately relative to judged evidence. For each query, we compare the optimized NONSENSE score to the highest-scoring judged query-relevant passage (QRP) under the same retriever. On SciFact, SciDocs, FIQA, and NFCorpus, NONSENSE frequently beats QRP across E5, BGE, and Contriever; on several pairs, success exceeds 0.95 and median corpus rank is 1. ArguAna/BGE is a useful boundary case, indicating that success depends on the model–dataset geometry rather than following automatically from the search procedure. Score curves show that the strings cross the QRP baseline after hundreds to thousands of proposals, then continue improving.

In a nutshell, this paper makes the following contributions: (i) a black-box, fixed-length character-replacement probe for dense retrieval that forbids query-term copying and produces visibly non-semantic strings; (ii) a QRP-relative evaluation showing that these strings frequently outscore the retriever’s strongest judged evidence and reach near-top full-corpus ranks; and (iii) budget, lexical, and ablation analyses showing that the effect is not explained by random strings, initialization choice, string length, or explicit lexical overlap.

2 
Related Work

Dense retrieval learns embedding spaces for nearest-neighbor search, from dual-encoder question answering to hard-negative training, distillation, and unsupervised contrastive learning 
(
Karpukhin et al., 2020
; 
Xiong et al., 2021
; 
Qu et al., 2021
; 
Hofstätter et al., 2021
; 
Izacard et al., 2022
)
. E5 and BGE are widely used embedding families 
(
Wang et al., 2022
; 
Xiao et al., 2024
)
; late-interaction and reranking models are stronger but costlier alternatives 
(
Reimers and Gurevych, 2019
; 
Khattab and Zaharia, 2020
; 
Nogueira et al., 2020
)
. Sparse lexical retrieval such as BM25 remains a standard comparison point 
(
Robertson et al., 1994
)
. Benchmarks such as MS MARCO, BEIR, KILT, SciFact, SciDocs, FIQA, NFCorpus, and ArguAna evaluate whether relevant documents are retrieved 
(
Nguyen et al., 2016
; 
Thakur et al., 2021
; 
Petroni et al., 2021
; 
Wadden et al., 2020
; 
Cohan et al., 2020
; 
Maia et al., 2018
; 
Boteva et al., 2016
; 
Wachsmuth et al., 2018
)
. NONSENSE asks the complementary question: can non-documents also become nearest neighbors?

Adversarial NLP has shown that character-, token-, and black-box methods can manipulate classifiers and entailment systems 
(
Ebrahimi et al., 2018
; 
Gao et al., 2018
; 
Wallace et al., 2019
; 
Jin et al., 2020
; 
Li et al., 2020
; 
Morris et al., 2020
)
, paralleling classic adversarial examples in vision 
(
Szegedy et al., 2014
; 
Goodfellow et al., 2015
)
. Behavioral testing motivates targeted probes beyond aggregate accuracy 
(
Ribeiro et al., 2020
)
, and retrieval poisoning injects adversarial passages into corpora or RAG pipelines 
(
Zhong et al., 2023
; 
Zou et al., 2025
)
. Our goal is narrower: remove payload semantics and lexical overlap to isolate a representational weakness in retrieval scoring geometry. The closer analogy is to fooling images: off-manifold inputs that receive high model confidence despite lacking human-recognizable semantics 
(
Nguyen et al., 2015
)
. We ask whether dense similarity can likewise be high for text that is not a passage at all.

3 
Method

Let 
 and 
 be the retriever’s query and passage encoders. For a query 
, NONSENSE maintains a fixed-length candidate string 
, initialized by repeating “
:::: 
” to 256 characters in the default setting. At each generation, the algorithm samples one mutable position and replaces its character with a visible character drawn from the active alphabet; with frozen spaces, positions initialized as spaces are never mutated. Query terms are lowercased alphanumeric spans matched by 
[a-z0-9]+
; any candidate containing a query term of length at least three is rejected before scoring. A replacement is accepted only if it improves cosine similarity 
. Thus the main experiment is fixed-length and replacement-only.

After 
 proposal steps, we insert the final evolved string into the full corpus and rank it by dense similarity. The key comparison is not only rank. For each query, we compute QRP as the highest-scoring judged query-relevant passage under the evaluated retriever, then report the NONSENSE score, QRP score, and success rate:

Metrics.

All table metrics are deliberately model-facing and easy to audit. 
QRP Score
 is the dense similarity score of the highest-scoring judged query-relevant passage (QRP) for that query. If several passages are judged relevant, we take the best-scoring one because it is the strongest clean evidence the retriever itself can provide. 
NONSENSE Score
 is the dense similarity score of the optimized non-semantic string for the same query. 
Success Rate
 is the fraction of queries for which NONSENSE Score is higher than QRP Score. 
Mean Rank
 and 
Median Rank
 are the full-corpus ranks of the inserted NONSENSE string after adding it to the corpus. This makes the failure relative and interpretable: a query is counted as a success only when the non-semantic string beats the retriever’s own best judged relevant passage.

4 
Experiments and Results

We evaluate E5-base-v2, BGE-base-en-v1.5, and Contriever on SciFact, SciDocs, FIQA, ArguAna, and NFCorpus, using 256 sampled queries, full-corpus ranking, and 50,000 proposal steps.

NONSENSE strings frequently outscore judged evidence.

Table 
1
 shows the central semanticity gap: optimized non-semantic strings frequently receive higher dense scores than the retriever’s strongest judged query-relevant passage. On SciFact, NONSENSE beats QRP for 97.7%, 85.2%, and 95.6% of queries for E5, BGE, and Contriever, with median rank 1 for all three; the pattern extends to SciDocs and FIQA, and is strongest on NFCorpus, where Contriever succeeds on 99.0% of queries. Across corpora ranging from 3.6k to 57.6k documents, these are not merely top-10 intrusions: NONSENSE strings frequently land at or near the top of the full corpus. ArguAna/BGE is the useful boundary: QRP remains slightly higher on average and success is 45.6%, showing that real semantic evidence can remain competitive when the model–dataset geometry is less permissive. This makes NONSENSE a diagnostic rather than a guaranteed attack: it identifies where dense neighborhoods admit off-manifold strings as stronger neighbors than judged evidence.

Optimization reaches the gap quickly.

Figure 
2
 shows that NONSENSE often overtakes QRP within 1k–5k proposals, with NFCorpus/E5 crossing by step 800 and SciDocs/E5 by step 1,400. Scores continue rising afterward, suggesting the effect is not merely favorable initialization. ArguAna/BGE again provides the boundary: its curve approaches but does not cross QRP, matching Table 
1
. Appendix Tables 
3
 and 
5
 show the same trend: overall QRP-relative success reaches 0.591 by 5k and 0.729 by 10k proposals, and the final median NONSENSE–QRP margin is positive for 14 of 15 dataset–retriever pairs.

Ablation and sensitivity analysis.

Appendix Tables 
2
 and  
5
 show that the effect is broad and robust. Margins are positive for 14 of 15 dataset–retriever pairs, and the mean score curves often overtake QRP within the recorded budget. On SciFact, mutable spaces, alternate initializations, and lengths 128/512 do not remove success. The no-letter setting is most restrictive, but remains nontrivial; Contriever still beats QRP for 56.6% of queries. Thus, letter-like material helps optimization, but lexical semantics are not required.

Controls rule out lexical copying.

Appendix Tables  
4
 and  
6
 separate the dense effect from trivial alternatives. Blank, random, and matched-random strings have near-zero success, while query-term repetition wins only by copying query terms and becoming a BM25 top hit. Optimized NONSENSE instead succeeds with zero query-term overlap and BM25@1 of zero in the SciFact control setting; across main runs, query-term rates are 0.000, BM25@1 is only 0.019, dictionary-word counts are essentially zero, and most characters are non-alphanumeric. Thus, the strings are model-input artifacts rather than readable evidence or lexical copies.

5 
Conclusion

NONSENSE shows that, in the evaluated dense retrievers, nearest-neighbor status and passage-like meaning can separate sharply. QRP-relative success asks whether a non-passage can beat the strongest judged evidence under the same model, score, and corpus; frequently, it can. Across five datasets and three retrievers, optimized non-semantic strings often outscore the retriever’s own highest-scoring judged relevant passage and rank near the top of the full corpus. Since the probe uses only black-box scoring, repeated queries can in principle synthesize strings that, if inserted into a searchable corpus, populate the index with non-semantic nearest neighbors. The resulting signal is diagnostic but operationally relevant: dense retrieval systems should not assume that high similarity is sufficient semantic evidence. Robust pipelines should audit negative neighborhoods and complement dense scores with lexical filters, passage-validity checks, or semantic verifiers before downstream use.

6 
Limitations

NONSENSE is an offline diagnostic for three English single-vector retrievers under exact dense scoring, leaving late-interaction, hybrid, reranked, ANN, multilingual, and RAG for future work. Optimized strings did not transfer reliably across retrievers, so the probe is currently model-specific. The strings are not human-facing evidence; they test whether dense similarity alone can rank non-semantic text above judged relevant passages.

Appendix A 
Detailed Experimental Setup

All main runs use 256 sampled queries per dataset and retriever, three seeds (4201–4203), and 50k proposal steps per query. The 256-query sample is drawn from the judged-query set for each dataset. This gives a fixed cross-dataset evaluation size while remaining below the smallest available BEIR test set in our study: SciFact has 300 test queries, NFCorpus 323, FIQA 648, SciDocs 1,000, and ArguAna 1,406. The choice also aligns with the batched GPU execution used by the optimizer, which evaluates one proposal per query in batches of 256.

We evaluate E5-base-v2, BGE-base-en-v1.5, and Contriever with cosine-normalized dense similarity. E5 uses the standard query and passage prefixes. For each dataset–retriever pair, we precompute full-corpus passage embeddings and rank the final NONSENSE string after inserting it into the complete corpus. The datasets cover scientific fact verification (SciFact), scientific document retrieval (SciDocs), financial question answering (FIQA), argument retrieval (ArguAna), and medical information retrieval (NFCorpus). Corpus sizes are listed in Table 
1
. We use judged relevant documents from the dataset qrels to define QRP. When a query has multiple judged relevant passages, QRP is the one with the highest dense similarity under the evaluated retriever.

Black-box access pattern.

The optimizer only queries the retriever as an embedding scorer. It does not use gradients, model weights, token-level saliency, or training data. Each proposal replaces one visible character, keeping the string length fixed, and is accepted only when the dense score improves. The query-term ban is applied before scoring a candidate, so accepted strings cannot succeed by copying obvious lexical evidence from the query. In the main setting, the edit alphabet is ASCII letters, digits, punctuation characters 
.,;:-_/\| #@%&*+=?!()[]{}
, and a small set of visible non-ASCII symbols. Spaces appear in the initialization; with frozen spaces, those positions are not mutated. We do not use hidden control characters. The final reported rank is computed only after the optimized string is inserted into the full corpus.

Compute and runtime.

Runs were executed in batched GPU jobs on H200 GPU nodes. A main run optimizes 256 queries jointly for 50k generations, proposing one replacement per query per generation and encoding valid proposals in batches of 256. Across the 45 completed main jobs recorded for the full run in the SLURM logs, wall-clock time ranges from 106.3 to 189.5 minutes per dataset–retriever–seed run, with mean 125.9 minutes and median 117.5 minutes. The method is therefore efficient as an offline audit: each run optimizes 256 queries in parallel, uses only black-box scoring calls, and can be distributed over datasets, retrievers, and seeds.

Reporting choices.

We report seed means in the main table because the optimizer is stochastic and the sampled query set depends on the seed. We keep the main metric set intentionally small: QRP score, NONSENSE score, QRP-relative success, and full-corpus mean/median rank. We omit BM25 from the main table because BM25 is a control rather than the evaluated dense model; the control-baseline appendix reports BM25@1 where lexical matching is the question.

Appendix B 
Interpreting the Control Baselines

The controls are designed to rule out three simple explanations. First, the blank and random-string rows test whether arbitrary off-manifold text is already highly ranked. They are not: success is essentially zero and mean ranks are in the thousands. Second, matched random edits test whether the large edit budget alone creates strong candidates. It does not. Third, query-term repetition verifies that a lexical copying baseline can win, while also showing why it is a different phenomenon: it copies query terms and becomes a BM25 top hit. Optimized NONSENSE provides the diagnostic contrast: it wins dense similarity without query-term overlap and without lexical retrieval success.

Budget and Lexical Diagnostics

This does not make the method a low-cost online attack, but it shows that the audit does not rely solely on an endpoint after exhaustive search.

 audits lexical leakage in the final main runs. The implemented query-term tests never fire in the final optimized strings: both substring and exact alphanumeric rates are 0.000. BM25@1 is low but not identically zero outside the SciFact control setting, which is why we treat BM25 as a diagnostic rather than as part of the main dense-retrieval claim.

Appendix D 
Tokenization and Lexical Audit Details

Table 
4
 is designed to distinguish dense-similarity success from readable evidence, lexical copying, and ordinary sparse retrieval. Query-term rates are computed after lowercasing and extracting alphanumeric spans with the same rule used by the optimizer. Exact Rate requires a banned query term to appear as a complete alphanumeric span, while Query-Term Rate also counts substring matches. Dictionary words are counted over alphabetic spans after lowercasing; the near-zero counts indicate that optimized strings rarely form ordinary English words. Alpha Tokens count alphabetic spans regardless of whether they are dictionary words, and Non-Alnum. reports the fraction of characters outside letters and digits.

These diagnostics are lexical rather than mechanistic. They do not identify which tokenizer units, embedding axes, or pooling behaviors produce high dense similarity. Instead, they establish the narrower claim needed for the main result: optimized NONSENSE strings beat QRP without obvious query copying, BM25 success, or readable word formation. A fuller mechanistic account of tokenization patterns and embedding directions is left for future work.

Appendix E 
Practical Audit Use

NONSENSE can be used as a stress test for a dense retriever before deployment. A practitioner can sample queries, run the black-box optimizer under the same encoder and preprocessing used in production, and compare optimized strings against the strongest judged or pseudo-judged relevant passages. High success is best interpreted as evidence that the embedding space contains non-passage nearest neighbors for those queries. Such systems may benefit from hybrid lexical-dense scoring, candidate-type filters, out-of-distribution detectors, cross-encoder verification, or reader-side evidence checks.

Appendix F 
Additional Scope Notes

The effect varies by model and dataset, with ArguAna/BGE providing a clear boundary case. This variation is useful: it suggests the probe can distinguish model–dataset pairs where off-manifold strings are easier or harder to place near queries. Future audits should test newer embedding models, larger and multilingual corpora, approximate-nearest-neighbor retrieval stacks, late-interaction and hybrid systems, semantic-verifier defenses, and mechanistic analyses of tokenizer and embedding-space behavior. Cross-encoder rerankers, hybrid lexical-dense scoring, and OOD filters are natural mitigation candidates for empirical evaluation.

Appendix G 
Diagnostic Interpretation

The results should be read as evidence about the geometry exposed by the evaluated scoring functions. QRP-relative success is intentionally stringent because QRP is selected by the same retriever being audited: the comparison asks whether the model’s own strongest judged evidence can be displaced by a non-passage under identical scoring. The lexical diagnostics then separate this effect from ordinary term matching. Taken together, the main table, score curves, and controls indicate that dense similarity can assign high rank to inputs that satisfy the model objective while falling outside the document assumptions under which retrieval outputs are normally consumed.

Table 
7
 reports cross-model transfer diagnostic. Strings optimized for a retriever usually remain strongest under that same retriever, while off-diagonal transfer is limited on SciFact, SciDocs, FIQA, and ArguAna. NFCorpus is the main exception: strings optimized for one model sometimes exceed another model’s QRP and can land within the first few hundred target-corpus ranks. This pattern suggests that NONSENSE is not merely a universal trigger shared by all encoders; much of the effect is model-specific, with some dataset-dependent shared vulnerability.
