Abstract.

Multi-hop retrieval-augmented generation (RAG) supports Web information seeking and fact verification by recovering complementary evidence across related pages within a limited retrieval budget. Scoring evidence independently against the original question can miss supporting units whose relevance emerges through intermediate facts. Iterative retrieval incorporates these facts into subsequent queries, while graph retrieval explicitly models relations among evidence units. Yet fixed-query graph retrievers update entity representations without adapting the query condition to accumulated relational context. We view multi-hop evidence recovery as the coupled evolution of evidence representations and query conditions, with accumulated context informing both what the retriever represents and how it searches for complementary evidence. QueryFlow realizes this perspective by recurrently integrating query-conditioned summaries of graph context into a shared query state, which controls boundary inputs and relation features for subsequent propagation. Across four representative multi-hop question answering (QA) datasets, QueryFlow achieves macro Recall@10 (R@10), Full Recall@10 (FR@10), and LLM-Acc gains of 4.98, 8.40, and 8.0 percentage points over representative baselines, respectively.

Keywords: 
GraphRAG, graph neural networks, graph-based retrieval, multi-hop question answering, web content mining

1. 
Introduction

Retrieval-augmented generation (RAG) grounds language-model answers in external evidence 
(
Lewis et al., 2020
)
. In Web content mining, it supports complex information seeking and fact verification across related pages 
(
Talmor and Berant, 2018
; 
Jiang et al., 2020
)
. Multi-hop questions make this evidence requirement more demanding because their answers depend on linked facts distributed across pages about related entities 
(
Ho et al., 2020
; 
Trivedi et al., 2022
; 
Yang et al., 2018
)
. Answering these questions requires retrieving evidence units, such as documents, passages, or chunks, that jointly support the necessary reasoning steps. A collection of individually relevant units can still omit a fact needed to complete the reasoning chain. Multi-hop retrieval is fundamentally an evidence-set recovery problem, with the goal of recovering the complete supporting set within a given retrieval budget. By improving multi-hop question answering over interconnected Web content, our work aligns with the 
Web Mining, Multimedia and Multilingual Content Analysis track.

Recovering a complete supporting set requires more than matching individual evidence units to the original question. Single-round dense retrievers learn semantic matches between questions and candidate evidence 
(
Karpukhin et al., 2020
)
, but independent scoring can miss complementary units whose relevance becomes apparent only after intermediate facts are found. Iterative retrieval addresses this limitation by conditioning subsequent searches on retrieved passages or intermediate reasoning 
(
Xiong et al., 2021
; 
Trivedi et al., 2023
)
. In these approaches, evidence dependencies are conveyed through retrieval history, leaving entity relations across documents implicit. Graph-based RAG makes these connections explicit through entities and relations 
(
Edge et al., 2024
; 
Zhu et al., 2025
)
, while neural graph retrievers learn to integrate connected evidence through query-conditioned message passing 
(
Li et al., 2025b
; 
Luo et al., 2025
)
. A central question in learned graph retrieval is how accumulated relational context should guide subsequent evidence acquisition. Fixed-query designs update entity representations while retaining the original query condition 
(
Luo et al., 2025
)
. As illustrated in Figure 
1
, identifying the author of 
The Hobbit
 shifts the remaining information need toward that person’s birthplace, while a fixed query can continue to favor book-related evidence. These designs accumulate relational context in entity representations without an explicit feedback path for that context to revise the query condition governing subsequent propagation.

The query state should evolve with the evidence representations it guides. Intermediate entities and relations can clarify what remains to be retrieved, so accumulated graph context should inform both the representation of evidence and the condition used to explore further evidence. Coupling these updates brings relational propagation and query adaptation into the same retrieval process, allowing newly established context to guide the recovery of missing support.

We introduce 
QueryFlow
, a graph retrieval framework that couples recurrent query evolution with evidence propagation to support multi-hop question answering. It maintains a shared query state alongside entity representations that accumulate relational context through message passing. Between successive propagation layers, query-conditioned attention summarizes all entity representations, making context distributed across the graph available to the query update. A gated recurrent transition integrates this summary with the preceding query state to revise the retrieval condition. Boundary feedback injects the updated state at question-linked entities, while relation feedback modulates the features used to transform neighboring messages. These interfaces change both the context injected into the graph and how evidence propagates across its relations, closing the feedback path from accumulated evidence to subsequent retrieval. Finally, entity scores are aggregated into a document ranking that supplies evidence for answer generation.

On four representative multi-hop QA datasets, QueryFlow achieves macro R@10, FR@10, and LLM-Acc gains of 4.98, 8.40, and 8.0 percentage points over representative baselines, respectively. Improvements in evidence coverage and complete recovery are accompanied by higher downstream QA reasoning accuracy, supporting the value of complete evidence retrieval for multi-hop question answering.

Our contributions are threefold.

•

We frame multi-hop graph retrieval as coupled evolution of evidence representations and query conditions, treating accumulated relational context as feedback for subsequent evidence acquisition.

•

We propose 
QueryFlow
, which couples recurrent query updates with graph propagation through boundary and relation feedback.

•

Experiments on four multi-hop QA benchmarks show gains over representative baselines in evidence recovery and answer accuracy.

2. 
Related Work

Relevance-based retrieval.

RAG integrates external evidence into language-model training or generation 
(
Lewis et al., 2020
; 
Guu et al., 2020
; 
Borgeaud et al., 2022
; 
Izacard et al., 2023
)
. Dense representations and token interactions improve matching between questions and evidence 
(
Karpukhin et al., 2020
; 
Izacard et al., 2022
; 
Khattab and Zaharia, 2020
; 
Santhanam et al., 2022
)
. Precomputed passage representations support efficient search, while token-level interactions retain fine-grained matching signals within each candidate passage. Better query representations, evidence fusion, and hierarchical indexing further improve evidence access and use 
(
Gao et al., 2023
; 
Izacard and Grave, 2021
; 
Shi et al., 2024
; 
Sarthi et al., 2024
)
. In single-round matching, retrieved evidence does not update the scoring condition, so complementary support with weak direct relevance can be missed. QueryFlow complements relevance scoring with feedback from accumulated relational context.

Iterative and adaptive retrieval.

Iterative retrievers use retrieved passages, condensed facts, or rewritten queries to guide later searches 
(
Qi et al., 2019
; 
Zhang et al., 2024
; 
Ma et al., 2023
)
. MDR re-encodes the question with earlier passages 
(
Xiong et al., 2021
)
, while Baleen condenses retrieved passages into facts for later hops 
(
Khattab et al., 2021
)
. Intermediate generation and reasoning also supply feedback 
(
Shao et al., 2023
; 
Trivedi et al., 2023
)
, while adaptive approaches control when and how to retrieve based on generation state or question difficulty 
(
Jiang et al., 2023
; 
Su et al., 2024
; 
Asai et al., 2024
; 
Jeong et al., 2024
)
. In retrieval loops driven by passages or reasoning, feedback passes through text history, leaving entity relations across documents implicit. QueryFlow brings this adaptation into graph propagation, using intermediate entity context to update the shared retrieval condition.

Graph-based retrieval.

Knowledge graph research also studies graph completion, which predicts missing entities or relations from graph structure. Completion methods learn multi-concept and fine-grained entity–relation representations 
(
Wang et al., 2023a
; 
Wang et al., 2024c
)
, or adapt how entity, relation, and temporal information is combined to predict missing facts 
(
Wang et al., 2023b
; 
Wang et al., 2024a
; 
Wang et al., 2024d
)
. Broader graph representation learning combines local and global signals for node classification, while attributed graph clustering uses collaborative graph augmentation and contrastive learning 
(
Wang et al., 2026
; 
Zhao et al., 2025
)
. These tasks learn graph representations or predict missing facts, whereas graph retrieval ranks source documents to recover evidence supporting a question.
Graph indices and diffusion associate evidence through explicit links 
(
Edge et al., 2024
; 
Guo et al., 2025
; 
Zhu et al., 2025
; 
Gutiérrez et al., 2024
; 
Gutiérrez et al., 2025
)
, while subgraph selection and path exploration construct structured context 
(
He et al., 2024
; 
Hu et al., 2025
; 
Li et al., 2025a
; 
Sun et al., 2024
; 
Luo et al., 2024
; 
Luo et al., 2026
)
. Learned relational reasoning supports query-conditioned propagation 
(
Zhu et al., 2021
; 
Zhu et al., 2023
; 
Galkin et al., 2024
; 
Zhuo et al., 2026
; 
Wang et al., 2024b
)
, and neural retrievers learn to aggregate or select connected evidence 
(
Sun et al., 2019
; 
Mavromatis and Karypis, 2025
; 
Li et al., 2025b
)
. Learned graph retrievers differ in how relational context conditions retrieval. GFM-RAG propagates entity relevance under a fixed query and maps it to documents 
(
Luo et al., 2025
)
, whereas D-RAG updates instructions from graph context for knowledge graph question answering 
(
Gao et al., 2025
; 
Zhuo et al., 2025b
; 
Zhuo et al., 2025a
)
. QueryFlow studies this interaction for complete document evidence recovery, using a shared evolving query state to control boundary inputs and relation features.

Final entity scores are aggregated into a document ranking for answer generation.

Experiments

Our experiments connect answer quality to the recovery of supporting evidence. We first compare generation and retrieval performance, then examine query evolution and its feedback interfaces through controlled interventions. Efficiency, retrieval budgets, and paired recovery analyses characterize the costs and conditions under which these gains occur.

Main Results

Table

RQ1.
 
How does QueryFlow compare with existing retrieval and reasoning methods on downstream answer generation?

Answer quality improves over representative baselines.

QueryFlow reaches macro LLM-Acc of 0.696 and Contain of 0.642. Relative to LinearRAG, these scores increase by 8.0 and 6.9 percentage points, respectively. The gains over GFM-RAG are 11.6 and 5.6 points. Both comparisons show improvements in judged correctness and inclusion of the gold answer.

The answer gains extend across all four benchmarks.

Compared with LinearRAG, LLM-Acc increases by 15.0 points on 2WikiMultiHopQA, 3.4 on HotpotQA, and 7.0 on both MuSiQue and ConcurrentQA. On MuSiQue, LLM-Acc rises from 0.369 to 0.439 while Contain improves from 0.332 to 0.375. QueryFlow improves both metrics on every dataset relative to LinearRAG and GFM-RAG, showing that the macro gains extend across all four collections.

Semantic correctness and answer inclusion improve together.

Contain gains range from 4.3 to 12.5 points over LinearRAG and from 3.8 to 7.5 points over GFM-RAG. For multi-hop questions, intermediate facts identify the entity or relation to which the final answer must refer. QueryFlow feeds this context into subsequent propagation to guide retrieval of complementary support. The gains in complete recovery examined in RQ2 are consistent with this explanation of the answer gains.

5. 
Conclusion

We presented QueryFlow, a graph retrieval framework that supports multi-hop question answering through coupled evidence propagation and query evolution. Accumulated graph context updates a shared query state, which controls subsequent boundary inputs and relation features. Across four multi-hop QA benchmarks, QueryFlow improves macro R@10, FR@10, and LLM-Acc over GFM-RAG by 4.98, 8.40, and 11.6 percentage points, respectively. At a budget of five documents, it also exceeds this baseline’s full recall at ten documents. Macro LLM-Acc also improves by 8.0 points over LinearRAG. Query-state interventions and interface ablations support the contribution of feedback within QueryFlow. The results connect evolving query conditions to more complete evidence sets and stronger downstream answers.

Appendix A 
Additional Experimental Details

A.1. 
Experimental Setup

2WikiMultiHopQA

This benchmark combines Wikidata relations with Wikipedia text to construct questions with explicit multi-hop reasoning paths 
(
Ho et al., 2020
)
. These annotations specify the intermediate relations linking a question to its answer, providing a structured basis for assessing evidence-set recovery.

HotpotQA

Questions draw on multiple Wikipedia documents and include comparisons between entities 
(
Yang et al., 2018
)
. Sentence-level supporting facts identify the evidence needed for an answer. We map these annotations to source documents to define the target evidence sets.

MuSiQue

MuSiQue composes single-hop questions into connected two- to four-hop questions 
(
Trivedi et al., 2022
)
. Intermediate answers link successive steps, reducing opportunities for disconnected reasoning and making subsequent evidence needs depend on earlier discoveries. We use the answerable examples.

ConcurrentQA

ConcurrentQA requires evidence from distinct public and private data distributions 
(
Arora et al., 2023
)
. We use the supplied documents as a shared retrieval collection to evaluate evidence recovery across heterogeneous sources with the same document-ranking interface.

Evaluation subsets.

Following GFM-RAG 
(
Luo et al., 2025
)
, LinearRAG 
(
Zhuang et al., 2026
)
, and Relink 
(
Huang et al., 2026
)
, we use fixed evaluation subsets. Matching LinearRAG’s reference question lists to source records yields 1,000 questions each for 2WikiMultiHopQA and HotpotQA, with HotpotQA drawn from distractor validation. For MuSiQue, we match the reference list to records in the answerable validation split. HotpotQA and MuSiQue are shuffled with seed 42 before matching; list membership determines selection. ConcurrentQA uses all 1,600 validation questions. Input sets are shared across methods. Retrieval metrics are averaged over questions with nonempty support sets (Section 
4.1
).

Retrieval corpora.

Supporting and distractor documents from the selected examples form each benchmark’s retrieval corpus. Table 
5
 reports selected input records and corpus sizes after preprocessing. Each question is evaluated against this collection, with 
 limiting the number of returned documents. Original support annotations define the target evidence sets.

A.2. 
Implementation Details

Model architecture.

The frozen 
all-mpnet-base-v2
 encoder supplies precomputed 768-dimensional question and relation embeddings, linearly projected to 
. The propagation operator uses the NBFNet formulation 
(
Zhu et al., 2021
)
. The retriever uses 
 layers with 512 hidden units, DistMult messages, sum aggregation, residual connections, layer normalization, and ReLU. The query controller also has 512-dimensional states. The full model enables both feedback interfaces with 
, attention temperature 1, and query-update dropout 0.

Optimization and hardware.

We train the retriever and query controller from random initialization on a single NVIDIA A100 using AdamW, learning rate 
, batch size one, gradient norm clipping at 1.0, and seed 1024. Activation checkpointing reduces propagation memory; the text encoder remains frozen.

Answer generation and judgment.

All methods generate answers with Qwen3.5-9B. Following LinearRAG 
(
Zhuang et al., 2026
)
, LLM-Acc records LLM judge acceptance; Contain checks for the normalized gold answer. Prompts, context handling, decoding, judge configuration, and output parsing are detailed in the supplementary code.

Document associations redistribute each entity’s score across its source documents. An entity appearing in one document contributes its full score there; one appearing in several documents divides that contribution equally among them. This property controls how graph relevance transfers to documents without selecting a fixed number of entities. Each document can still accumulate contributions from multiple entities, so its rank depends on their combined relevance and document frequencies. The weighting acts on entity frequency rather than normalizing by document length.
