Abstract

Protein-complex structure prediction with AlphaFold 3 depends on MSA content, depth, and cross-chain pairing.
Current pipelines apply uniform recipes, typically maximizing depth and pairing by species, yet even whether cross-chain pairing helps AF3 remains contested.
We show that the value of both depth and pairing is strongly target-dependent, so no single recipe is optimal across interfaces.
We introduce an autonomous agent that treats a frozen AF3 as a
black-box experimental instrument.
For each target, the agent formulates biological hypotheses, analyzes and reorganizes the MSA, and iteratively refines sequence selection and pairing using predictor label-free signals alone.
On 1,015
protein–protein interfaces from three benchmarks released after AF3’s
training cutoff, the agent improves overall interface DockQ over AF3’s
default pipeline and fixed MSA recipes on every benchmark, while using on average
60% fewer MSA sequences than the default.
Gains are largest for inter-species heteromers, where species-based pairing is unreliable: mean DockQ increases from 0.465 to 0.612 on FoldBench and from 0.482 to 0.562 on HD439.
The improvements arise from both sequence construction and pairing policy, including deliberate non-pairing.
These results recast MSA design as a target-specific problem and show that an autonomous agent can adapt it at test time through biological reasoning and self-directed, confidence-guided experimentation.

Introduction

Deep learning has transformed protein structure prediction. AlphaFold2 (AF2)

(
Jumper et al., 2021
)
 achieves near-experimental accuracy for many
proteins by exploiting co-evolutionary signals in multiple sequence alignments
(MSAs): by aligning homologous sequences, MSAs reveal conserved positions and
correlated substitutions that constrain residue–residue contacts. For
complexes, the same principle extends across chains. AlphaFold-Multimer

(
Evans et al., 2021
)
 and AlphaFold3 (AF3)

(
Abramson et al., 2024a
; 
Abramson et al., 2024b
)
 combine
unpaired MSAs for each chain with paired MSAs, in which homologs of different
chains are matched by species so that correlated substitutions across the
interface inform inter-chain geometry; RoseTTAFold 
(
Baek et al., 2021
)

relies on MSA features in a similar way.

Prediction accuracy therefore depends on MSA quality, which varies
substantially across targets: sparse, redundant, or incomplete alignments
can limit accuracy. One response is to bypass alignments altogether.
MSA-free predictors such as ESMFold 
(
Lin et al., 2023
)
 and
HelixFold-Single 
(
Fang et al., 2023
)
 instead encode
evolutionary regularities in protein language models.
Like MSA-based methods, however, their accuracy decreases for targets with
few homologs 
(
Lin et al., 2023
; 
Fang et al., 2023
)
.
For heteromeric complexes, recent benchmarking 
(
Luo et al., 2026
)

challenges the assumption that precise cross-chain pairing is essential:
on average, increasing the depth of unpaired alignments helps AF3 as much
as or more than species-based pairing, a trend that extends to antibody–antigen
complexes. These findings, however, concern a single construction axis,
depth versus pairing, and are reported as aggregate trends; how this axis
interacts with other construction choices, and whether such trends hold
for individual targets, remains untested.

This ambiguity calls for an agent that decides, for each target, how deep to search, what to filter, and how to pair sequences, and that refines these decisions using feedback from downstream structure prediction.
Evaluator-guided LLM auto-research offers a relevant precedent. In combinatorial optimization and algorithm design, FunSearch 
(
Romera-Paredes et al., 2024
)
, EoH 
(
Liu et al., 2024
)
, ReEvo 
(
Ye et al., 2024
)
, and AlphaEvolve 
(
Novikov et al., 2025
)

use LLMs to search over programs scored by an evaluator, discovering heuristics that outperform hand-designed ones.
These successes rest on two conditions: instances are homogeneous, so one program serves the whole problem class; and the score is the objective itself (e.g., tour length or number of bins), so optimizing it solves the task. MSA construction satisfies neither:

•

Target-dependent optima.
 Proteins differ widely in family size and diversity of available homologs, so a strategy that works well for one target often fails to transfer to another.

•

No ground-truth signal as guidance.
 For a new target the true structure is unknown, and the only available feedback is AlphaFold3’s confidence scores (e.g., pLDDT, ipTM) 
(
Abramson et al., 2024a
)
, which are the model’s own estimates of accuracy rather than measurements of it. Optimizing them directly risks exploiting their miscalibration, so they must be weighed against direct analysis of the MSA and predicted structure.

The central challenge is therefore not to find a single better heuristic, but to build a general-purpose environment in which an agent can explore, reflect, and refine a construction strategy for each new target. Our contributions are:

•

Auto-Research Agent.
 We introduce an autonomous agentic framework that keeps the structure predictor in the loop. The agent iteratively proposes, evaluates, and refines target-specific MSAs using only the predictor’s label-free feedback.

•

SOTA Performance.
 Across three protein–protein benchmarks, the agent consistently improves over AF3-Default setting and other heuristic strategies, while using substantially shallower MSAs, with average depth reduced by approximately 60%.

•

Target-specific MSA reasoning.
 The agent’s key capability is to turn target-specific biological diagnoses into an iterative hypothesis-testing process, reading the predictor’s confidence feedback to refine its MSA construction step by step.

Related Work

MSA construction and pairing.

Building an MSA for a complex involves two decisions: how deep each chain’s
alignment is, and how its rows are paired across chains.

Retrieval
 tools such as JackHMMER 
(
Eddy, 2011
)
, HHblits

(
Remmert et al., 2012
)
, and MMseqs2 
(
Steinegger and Söding, 2017
)
, as used in
ColabFold 
(
Mirdita et al., 2022
)
, determine each chain’s depth and diversity.

Pairing
 methods then match rows across chains, using species and genomic
proximity 
(
Mirdita et al., 2022
)
, coupling or mutual-information objectives

(
Bitbol et al., 2016
; 
Bitbol, 2018
)
, or differentiable matching

(
Lupo et al., 2024
; 
Lupo et al., 2025
)
.
Which decision matters more is contested: across hundreds of heterodimers,
most reported pairing gains stem from the accompanying increase in depth

(
Luo et al., 2026
)
.

Portfolio-based
 pipelines hedge across these choices by generating
alternative inputs for each target and keeping the best: DeepMSA2

(
Zheng et al., 2024b
)
 selects among MSAs from hierarchical database searches
using AlphaFold-based scores; MULTICOM 
(
Liu et al., 2023
; 
Liu et al., 2025
)

builds alternative alignments, templates, and paired MSAs from multiple sources of
evidence; and CAF3 
(
Neupane et al., 2026
)
 evaluates pre-enumerated MSA and template
variants for AF3.
These pipelines adapt to each target only through selection: candidates are
produced by fixed rules, and the scores do not inform which new candidates to
generate.

Autonomous research agents.

LLM agents increasingly conduct research in a propose–evaluate–revise loop.
In domains with reliable evaluators, they evolve programs and heuristics
against executable scores

(
Romera-Paredes et al., 2024
; 
Novikov et al., 2025
; 
Liu et al., 2024
; 
Ye et al., 2024
)

and automate machine-learning research whose experiments return measurable
outcomes 
(
Lu et al., 2024
; 
Schmidgall et al., 2025
)
. Because the
evaluator is trustworthy, research reduces to optimizing against it. Agents in chemistry and biology, by contrast, have primarily served a different role: orchestrating specialized domain tools to plan experiments, analyze intermediate results, or execute established research workflows

(
Bran et al., 2024
; 
Ghafarollahi and Buehler, 2024
; 
Shen et al., 2024
; 
Xin et al., 2024
; 
Sinclair et al., 2025
; 
Qu et al., 2026
)

rather than iterate toward an objective. When they do iterate in silico, they
score candidates with computational proxies such as predicted structure
confidence 
(
Swanson et al., 2025
)
, implicitly treating these proxies as
ground truth; trustworthy closed-loop feedback has so far required physical
experiments 
(
Boiko et al., 2023
)
.

Proteins, Complexes, and MSAs.

Proteins are chains of amino acids (20 common types); writing each as a letter turns a protein into a string, its 
sequence
. Many proteins function as complexes of several chains, which fall into three categories: 
homomers
 (identical chains), 
intra-species heteromers
 (distinct chains from one organism, e.g., hemoglobin’s 
 and 
 chains), and 
inter-species heteromers
 (chains from different organisms, e.g., a viral protein bound to a host receptor, or an antibody bound to an antigen). 
Homologs
 are proteins in different species that descend from a common ancestral gene and share similar sequences and structures. A multiple sequence alignment (MSA) aligns a query’s homologs so that corresponding positions share a column. Because residues in spatial contact tend to mutate together, co-varying columns indicate structural proximity. A single-chain MSA captures only intra-chain coevolution. A 
paired
 MSA extends this signal across chains by matching each chain’s homologs by source species, so each row holds proteins from one organism. Pairing therefore mainly benefits intra-species heteromers, whose chains coevolve within one organism.

Methodology

4.1 
Overview

We formulate the design of MSA representation as an autonomous agentic exploration process.
The framework comprises three components: 1) the agent that iteratively proposes MSA representation; 2) the predictor 
 such as AF3 that generates structure predictions from each proposal; and 3) the runtime environment that executes tool calls, enforces budgets, and manages the prediction-derived signals observed by the agent.

Concretely, given a multichain complex target 
, the agent constructs an initial 
MSA representation proposal
 
 that includes unpaired MSAs for every chain and paired MSAs across chains (Preliminaries 
3
). The agent then enters an iterative refinement process. In each round 
, it submits 
 to 
 and receives prediction-derived feedback signals 
 as observables. This feedback is derived exclusively from the outputs of G and does 
not
 require access to the ground-truth structure (Appendix 
A
). Based on this feedback, the agent may write and execute its own analysis programs before producing a refined proposal, 
.

This proposal–feedback cycle continues until the submission budget is exhausted or the agent concludes further improvement is unlikely. Finally, the agent nominates one MSA representation 
 from its previous proposals. We evaluate 
 by submitting it to 
 and comparing the resulting predicted structure with the ground-truth structure. We then get the evaluation signal 
 using DockQ, as defined in Preliminaries 
3
.

It is worth noting that, in our main experiments, the runtime exposes only 
 to the agent. It computes 
 silently and never exposes these signals through the agent’s context or workspace. As an ablation study, we consider an oracle setting in which 
 is visible to the agent, as described in Appendix 
F
.

4.3 
Runtime and Workspace

The runtime separates what the agent sees from what it keeps: the LLM
context is reset every round (Section 
4.2
), whereas an
episode-scoped workspace persists. This section
describes the workspace, the sandbox in which analysis code runs, and how
the runtime validates actions and enforces budgets.

Workspace.

Each episode has a private workspace. The runtime writes the target
inputs into it at the start of the episode and adds predictor feedback
after each valid submission, restricted to what the current execution
profile makes visible. The agent adds its own files, such as analysis
programs, derived statistics, notes, and candidate MSA organizations,
through 
analysis
. The runtime thus supplies the target and the
predictor signal, while the agent decides how to process that signal and
what to keep. Workspace files never enter the context automatically and
must be read through 
analysis
. The folder layout is given in
Appendix 
E

Analysis sandbox.

Rather than a fixed set of analysis tools, the agent receives a
general-purpose programming environment, so it can decide which evidence
matters for a given target and compute it itself. Each 
analysis
 call specifies an objective and a Python
program, which runs in a fresh, isolated process. The process may read
the target inputs, visible predictor feedback, and existing workspace
files, and may write only to the agent-writable part of the current
workspace. Network access is disabled to prevent ground-truth leakage.
The process terminates after the call, and its textual output is
appended to the context as 
.

Action validation.

The runtime checks every action against its schema before execution,
including proposal submissions and memory entries. A failed check is
returned as the tool output and followed by another LLM turn; it changes
the context but not the proposal, the memory, or the predictor-call
count. If a turn contains no action, the runtime appends a continuation
instruction.

Budgets and termination.

Each episode has an LLM exploration budget and a submission
budget. Every LLM turn during exploration, including reflection
and correction turns, counts toward the former; each successfully
completed submission counts toward the latter. Once the LLM
exploration budget is exhausted, analysis and new submissions
are disabled. Up to two additional LLM turns are reserved for
any pending round summary and 
finish
; these turns are
included in the reported LLM-call total. The episode is marked
unsuccessful if the required finalization is not completed
within the allowed calls.

Experiment Set-up

5.1 
Benchmark Datasets

We evaluate on three protein–protein interface benchmarks comprising 1,015
interfaces in total, all released after AF3’s training cutoff (details in Appendix 
B.2
 and 
B.1
).

FB-v1-pp
 (278 interfaces; 194 homomeric, 84 heteromeric) is the protein-protein subset of the published FoldBench benchmark 
(
Xu et al., 2026
)
.
It excludes interfaces similar to AF3’s
training data at the chain and whole-complex level, so that accuracy
reflects what AF3 infers from the input MSA rather than what it has
memorized.

FB-v2-pp-hard
 (299 interfaces; 168
homomeric, 131 heteromeric) is a hard subset of FoldBench-v2 currently under development. It retains only interfaces
whose local binding geometry and residues differ substantially from
AF3’s training set.

HD439
 (438 heteromeric
interfaces) is a public benchmark  
(
Luo et al., 2026
)
 comprising entirely of heterodimers: 99
inter-species and 339 intra-species pairs.

5.2 
Agent Setup

Predictor.

We use AlphaFold 3 (v3.0.2) as 
 with the FoldBench
inference protocol 
(
Xu et al., 2026
)
: 10 recycles and five
diffusion samples for each of five fixed random seeds, shared across
all targets and conditions, giving 25 structures per submission.
Within each target, all conditions also use the same query sequences
and templates, so differences in predicted structures arise from the
MSA input alone.
The default condition uses the MSAs and species-based pairing of AF3’s standard data
pipeline. Agent proposals instead specify each chain’s MSA row by row;
homologs placed in the same row across chains form one row of the
complex MSA, so the agent controls both which sequences are included and
which are paired across chains (Appendix 
B.4
).

LLM Setting.

The agent uses GLM-5.3 with temperature 0.2, maximum reasoning effort,
and a maximum response length of 32,768 tokens. Each target is
processed in an independent episode whose first proposal is the
AF3-Default control (Appendix 
B.5
).

Budget Setting.

Each episode allows at most 60 completed generator runs, including the
initial Default proposal, and 600 LLM calls in total. Failed or invalid submissions are not
counted, and the agent may stop early by nominating a final proposal 
. The analysis Python program has a execution time limit 120s (Appendix 
B.6
).

5.3 
MSA Input Baselines

We compare our agent with the following baselines:

AF3-Default
 is the initial MSA proposal generated by AF3 Default pipeline. It is submitted directly to the predictor without iterative refinement or proposal selection.

mMSA
 is the fixed MSA representation strategy where only monomeric alignments are provided, without additional cross-chain pairing.

pMSA
 is the strategy in which the monomeric alignments are supplemented with cross-chain paired sequences.

uMSA
 is the strategy in which the monomeric alignments are supplemented with unpaired UniProt hits.

Controlled comparisons.

The agent and AF3-Default always start from identical MSA resources, so
Agent vs. AF3-Default is our primary comparison: it isolates the effect
of iterative refinement and proposal selection. The three other
baselines are controlled with respect to one another, but not always
with respect to the agent. On the FoldBench sets, they are built from
separate HHblits and UniProt searches. Because pMSA and uMSA draw on the
same pool of hits, their difference isolates the effect of pairing, but
their differences from the agent also reflect MSA source and
construction. On HD439, the agent and all baselines use the MSAs
released with the benchmark 
(
Luo et al., 2026
)
, whose
unpaired, paired, and UniProt-enriched variants serve as mMSA, pMSA,
and uMSA, so all comparisons there are input-matched. Implementation
details are given in Appendix 
B.3
.

6.2 
Construction quality matters more than depth.

Depth does not explain the gains.

Among fixed heuristics, depth matters more than pairing: on the
FoldBench sets, where pMSA and uMSA share the same hits, adding them
unpaired generally outperforms pairing them, consistent with

Luo et al. (2026)
 on HD439. The agent reverses this intuition.
Its nominated MSAs average only 40% of AF3-Default’s depth, and half
retain fewer than 20% of its rows (Appendix Table 
2
); since
AF3-Default and uMSA have similar depths, the same holds relative to
uMSA. Yet these much shallower MSAs outperform both.
Shallowness alone is not the cause: mMSA is even shallower on FBv1 and FBv2
but yields lower DockQ (Table

From biological judgment to target-specific MSA proposals.

Analyzing agent’s episode trajectories revealed a common pattern: the agent grounds its decisions in biological knowledge and, through iterative submissions, distills them into explicit and reproducible selection procedures.

For example, 8P9C is a complex comprising the tetramerization domains of p63 and p73, two paralogous members of the p53 family, and DARPin 1810 F11, a designed ankyrin repeat protein with no natural orthologs 
Strubel et al. (2023)
. Its homologs therefore come from the large natural ankyrin-repeat family. In the default input, 84.5% of the 16,384 rows contained only DARPin sequences, resulting in a mean DockQ of 0.048. The agent separated p63 and p73 candidates to limit paralog mixing, paired them by species, and restricted DARPin sequences to a small, filtered supplement. The selected MSA contained only 425 rows and reached a mean DockQ of 0.866.

Another example, 7R86, pairs the leucine-rich repeat domain of the mouse Nogo receptor RTN4R with the third thrombospondin type 1 repeat of the adhesion GPCR BAI1 
Wang et al. (2021)
. Both are widespread repeat modules, so a single species can contribute many candidates for each chain. Species matching therefore yielded 8,191 pairs, while chain B lacked an unpaired alignment (mean DockQ 0.037). The agent kept only 78 high-identity pairs as likely orthologs and recovered 472 B-only rows from the pairing candidate pool, reaching a mean DockQ 0.921.

Across examples, the agent applied a shared biological reasoning framework but adapted its MSA construction to each target. The agent can, for example in the case of 8P9C, design its own ablations to show that both expanding the DARPin supplement and removing selected pairings substantially degraded performance. Notably, agent resolved these choices using predictor confidence alone, without access to DockQ. This demonstrates the agent’s ability to turn biological hypotheses into target-specific decisions through iterative experimentation.

7 
Conclusion

We introduced an autonomous research agent that optimizes MSA representation for protein-complex structure prediction at test time. Using a frozen predictor’s confidence signals, the agent writes and executes analyses, accumulates evidence in memory, and adapts unpaired MSA depth and cross-chain pairing for each interface without ground-truth structures or gradients. Across FoldBench-v1, FoldBench-v2, and HD439, this approach improves overall average accuracy and confidence-based model selection, with smaller gains in best-case accuracy. The discovered strategies also provide insight into the target-dependent value of pairing and depth. Together, these findings establish adaptive MSA representation as an effective training-free approach and demonstrate how autonomous agents can use model feedback to investigate and improve inference in structural biology.

We impose no fixed scalar combination of these signals and no rule requiring
maximization of mean ipTM.
In the blind setting, neither search nor final selection has access to
ground-truth target structures or evaluation metrics such as DockQ;
these are used only for offline evaluation.

Appendix B 
Experimental Details

B.1 
Prediction Targets and Interface Definition

A prediction target 
 is the complete complex in one AF3 input. The agent optimizes MSA organization for the complex, so all evaluated interfaces within that target share one trajectory and final selection 
. Each benchmark-listed interface is a separate evaluation entry, identified by its reference assembly and a pair of chain-copy identifiers. For evaluation, predicted chain copies are matched to their corresponding copies in the reference structure. Copies of the same protein entry share the constructed MSA but retain distinct chain identifiers for evaluation. The agent sees the complete complex, without benchmark interface annotations or knowledge of which interfaces are evaluated.

Controlled baselines on FoldBench.

The controlled baselines share a monomeric alignment generated by HHblits against Uniclust30 (

•

•

Candidate rows are sorted by the product of their original per-entity row indices, with ties broken by the index sum, within-group rank, and TaxID. B.5 
Agent Configuration

Language model.

We use GLM-5.3 with temperature 0.2, reasoning effort set to

max
, and a maximum response length of 32,768 tokens.
Each target is processed in an independent episode with no
information shared across targets.
We accessed the model via the Zhipu GLM Coding API during
September 11–22, 2026 (UTC+8), with the API-reported model
identifier 
glm-5.3
. Table 
4
 reports the mean and median
numbers of LLM calls per target, as well as the total token usage
for each dataset.

Initial proposal.

The initial proposal 
 is the Default condition, i.e.,
AF3’s default processing of the prepared source MSAs for FoldBench-v1 and FoldBench-v2, and the publicly released MSA files for HD439. Query
sequences, templates, and predictor settings remain fixed across
all subsequent proposals.

Proposal generation.

The LLM writes complete Python programs to select, filter, combine, reorder, or pair MSA rows using available inputs and accumulated observations. No fixed transformation library or scalar reward is imposed; the agent uses AF3 confidence, cross-sample consistency, and structural and biological plausibility to guide its search.

Before AF3 inference, the host validates the candidate JSON and required protein entities. For manually constructed MSAs, it checks query headers, alignment lengths, equal row counts across chains, and the specified paired-row correspondence. Gap-only rows are permitted for unpaired homologs. Invalid candidates are returned to the agent for correction without running AF3.

Programs run in an isolated Python sandbox with a 120-second limit per execution. The agent can access provided AF3 inputs, earlier observations, and prediction artifacts, but has no network access or access to ground-truth structures and evaluation results.

Final nomination.

At termination, the LLM nominates one successfully evaluated
proposal 
, with the initial Default as an eligible choice,
and provides a rationale. Conflicts among proxy metrics are
resolved by the LLM’s contextual judgment, without prescribed
metric weights or priorities. The prediction ensemble already
computed for the nominated proposal is used for final evaluation;
no additional inference is run. The mean and median numbers of successful submissions per target,
including the initial Default, are reported in
Table 
4
.

Isolation from ground truth.

Ground-truth structures and all reference-based evaluation results,
including DockQ, are withheld from the agent throughout exploration
and nomination. DockQ is computed separately and used exclusively
for offline evaluation.

B.6 
Budgets and Accounting

Each episode permits at most 60 successful predictor submissions,
including the initial Default, and 600 agent-side LLM calls during
exploration. A submission is counted only after input validation and
successful predictor inference; invalid inputs and failed predictions
do not count, while an invocation that succeeds after internal retries
counts once. All exploration-stage LLM calls count toward the
600-call limit, regardless of purpose. Backend or service retries
within a single provider invocation do not count as separate calls.

If this LLM limit is reached before a valid final nomination, analysis
and predictor submissions stop. Up to two additional LLM calls are
allowed solely to finalize the episode: the agent first completes any
pending round summary, then nominates a previously completed proposal
via 
finish
. If no summary is pending, it nominates directly
and may retry once if the nomination is invalid. The episode ends
upon a valid nomination.

B.7 
Evaluation Metrics

Interface accuracy is measured with DockQ, computed using the
DockQ implementation in OpenStructure 2.11.1 through the
FoldBench evaluator and its reference-to-prediction chain
mapping (Appendix 
B.1
). For each interface and experimental
condition, the primary reported DockQ value is the arithmetic
mean of the scores across all 25 predicted structures
(five seeds with five samples per seed). The same aggregation
is applied to all experimental conditions.
