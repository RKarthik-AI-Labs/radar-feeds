Abstract

Explanation APIs are often treated as increasing model-extraction risk, but an end-to-end attack comparison cannot show whether an explanation reveals model-specific information or merely supplies a convenient next-query coordinate. We study this distinction for explanation-guided extraction of tabular classifiers. We separate an explanation into an 
attribution
 channel, which ranks influential features, and a 
coordinate
 channel, which supplies candidate feature values for perturbing those features. We then test whether the useful bin edges are privileged to the service or reproducible from the adversary’s own data.

Across six datasets and five target families, using attribution rankings to choose which features to perturb provides no systematic extraction advantage. 
Lime
’s discretization bin edges can improve fidelity by up to 
 percentage points on continuous features, but those edges are quantiles of the explainer’s background data rather than properties of the target model. In controlled comparisons, an attacker-side grid reproduces the useful bin-edge gains without querying an explanation API. We use these findings to derive 
Cutpurse
, which combines a self-computed grid with diverse query generation and boundary search. Against a service that withholds bin edges, 
Cutpurse
 improves fidelity by 
 percentage points on continuous-feature targets. It also exceeds the undefended published attack by 
 percentage points. Thus, withholding default 
Lime
 bin edges alone does not prevent effective extraction under the in-domain auxiliary-input, probability-output, and same-family surrogate assumptions studied here. Our results concern default 
Lime
 and 
Shap
 configurations for tabular classifiers. They do not establish the same conclusion for other explainers, target classes, or data-free attackers.

I 
Introduction

Machine learning services increasingly return a post-hoc explanation alongside each prediction. This practice improves transparency, but it also raises a security question: does an explanation endpoint give a model-extraction adversary a capability that prediction access alone cannot provide? Model extraction builds a surrogate that agrees with a black-box target on unseen inputs 
[
1
, 
2
]
. High-fidelity extraction compromises model confidentiality and can support offline transfer-based attacks 
[
1
, 
3
, 
4
]
. It can also amortize the target-query cost of downstream membership inference 
[
5
]
.

We take Autolycus 
[
6
]
, an explanation-guided extraction attack against interpretable tabular classifiers, as our starting point. It couples the feature information returned by 
Lime
 or 
Shap
 with a traversal that generates new queries. Its evaluation shows that this complete attack can extract models effectively under a limited query budget. It does not, however, isolate how much the explanation outputs (feature rankings and LIME bin edges) and the traversal each contribute to that performance. 
Lime
 provides both a feature ranking and bin edges, while 
Shap
 provides feature attributions without bin edges. Even if an explanation output helps, it remains unclear whether it reveals information specific to the service or information the attacker can approximate from its own data. These distinctions determine whether the explanation API provides a model-specific capability or merely a convenient query-placement aid.

We decompose the information Autolycus consumes into two channels. The attribution channel ranks influential features. The bin-edge channel supplies candidate feature values for perturbing those features. This decomposition lets us test each channel while holding the rest of the attack fixed. It also gives a controlled test for a service-specific disclosure. We compare the service’s bin edges with equivalent edges that the adversary estimates from its own auxiliary data.

The resulting diagnosis also motivates 
Cutpurse
. Autolycus explores outward from a small seed set, so it can miss regions that no seed reaches. It also does not actively search between opposite-class samples for a decision crossing. We address these limitations with diverse query generation and boundary search. For bin-edge placement, 
Cutpurse
 fits 
Lime
’s default discretization grid to its own auxiliary inputs. It combines this auxiliary grid with the two traversal components and never calls an explanation API. Section 
V
 derives these three design choices.

Contributions

•

A channel decomposition of explanation-guided extraction.
 We separately evaluate feature selection by attribution ranking and 
Lime
 bin edges in the base Autolycus traversal. Across six datasets and five target families, ranking-based selection provides no systematic advantage, whereas bin edges can improve fidelity by up to 
 percentage points on continuous-feature targets (§
VI-B
–
VI-C
).

•

A controlled test of service-specific bin-edge information
 For LIME’s default quartile discretizer, bin edges are quantiles of the explainer’s background data, not properties of the target model. Under the auxiliary-input conditions studied, attacker-fitted grids reproduce similar bin-edge gains. Grids fitted on small initial seed pools retain most of these gains. A sensitivity check with LIME’s label-dependent entropy discretizer gives the same qualitative result.

•

A constructive explanation-free attack.
 
Cutpurse
 combines an attacker-computed grid with established diversity and boundary-search techniques and makes no explanation calls. On continuous-feature targets, it improves fidelity by 
 percentage points over the defended Autolycus configuration and by 
 percentage points over Autolycus with bin edges available (§
VI-E
). It demonstrates that an adaptive attacker can recover useful query-placement capability independently of the explanation API under the studied assumptions.

Scope

We study one family of explanation-guided attacks on interpretable tabular classifiers. Our results do not imply that explanations are harmless in general. These conclusions may not extend to other explanation methods or configurations, high-dimensional or neural targets, or data-free attacks.

II 
Background and Related Work

II-A
 
Model Extraction and Post-hoc Explanations

Model extraction attacks reconstruct a functional copy 
 of a black-box target 
 from query access alone, with success measured by prediction agreement between 
 and 
 on held-out data (formalised in §
III
). When the target is deployed as an explainable service, each query returns not only a label but a post-hoc explanation, which may reveal additional structure about 
. Two dominant explanation families expose fundamentally different information:

•

Shapley-based feature attribution (SHAP)
 SHAP 
[
7
]
 assigns each feature a signed magnitude 
, its Shapley marginal contribution to the prediction at 
. This is a statement of how much each feature matters locally. It carries no explicit information about where along a
feature axis the decision changes.

•

Local surrogate explanation (LIME)
 LIME fits an interpretable model to a discretized neighbourhood of 
. Continuous features are binned, and the returned coefficients are attached to 
 pairs. LIME therefore reveals both an influential feature and the bin edge of the local discretization bin.

This distinction between feature rankings alone and feature rankings accompanied by
local bin edges is central to our analysis. We test whether the base Autolycus traversal benefits from using an attribution ranking for feature selection and whether it benefits from LIME bin edges (§
III
, §
IV
).

II-B
 
Related Work

Model Extraction Attacks

Model extraction attacks aim to reconstruct a functional copy of a black-box target model through strategic querying 
[
1
]
.
Early work by Lowd and Meek framed adversarial classifier reverse engineering from query access 
[
8
]
.
Tramèr et al. 
[
1
]
 demonstrated that
simple equation-solving over prediction outputs suffices for linear models.
Subsequent methods scaled to neural networks: Knockoff Nets 
[
9
]

trains a surrogate on outputs obtained by querying with a knock-off dataset,
while Jagielski et al. 
[
2
]
 show that high-fidelity extraction
of deep networks is possible given sufficient queries.
Other work has examined extraction from complementary perspectives, framing it as knowledge distillation 
[
3
, 
10
]
 or active learning 
[
11
]
, where queries are selected to efficiently transfer or recover the target model’s decision boundary.
This line of work has also motivated the defence methods, for example, Juuti et al. 
[
12
]
 propose PRADA, which detects anomalous query distributions
associated with DNN model-stealing attempts.
More recently, Marich 
[
13
]
 formalises the problem as distributional equivalence
and proposes an active sampling strategy that maximises information gain per query.
In contrast, our method requires only a small per-class seed set rather than a large
public transfer set, and synthesises informative queries from that seed.

Explanation-Guided Extraction

The observation that post-hoc explanations leak structural information about the
target model motivates a distinct attack family.
Milli et al. 
[
14
]
 first demonstrated that gradient-based explanations
suffice to reconstruct linear models exactly.
Miura et al. 
[
15
]
 (MEGEX) carry gradient explanations into the data-free setting: treating the returned gradient as a derivative signal, the adversary trains a generative
model that synthesises its own queries, so no real input data is needed. Both exploit a property our

Shap
 and 
Lime
 setting lacks, namely that a gradient specifies a direction in
input space rather than only a per-feature magnitude.
Autolycus 
[
6
]
 extended this to classical ML classifiers
(decision trees, logistic regression, naive Bayes, and 
-NN) by using LIME and SHAP
explanations as traversal guides: the attacker perturbs seed samples along the
directions of highest feature attribution, progressively labelling a synthetic dataset
to train a surrogate. Yan et al. 
[
16
]
 (XaMEA) similarly
exploit the spatial information contained in explanations in a model-agnostic manner.
Our question is narrower than whether explanations help extraction in general. For the default LIME and SHAP configurations used by Autolycus, we separately test the attribution ranking and LIME bin edges. We also test whether the bin edges supplied by the service outperform a grid fitted by the adversary.

Counterfactual-Based Extraction

A growing body of work exploits counterfactual explanations (CFs) rather than
attribution scores.
Aïvodji et al. 
[
17
]
 first showed that CFs leak enough
boundary information to build high-fidelity surrogates, and DualCF 
[
18
]

improved query efficiency by training on CF/counter-CF pairs that
straddle the decision boundary.
Khouna et al. 
[
19
]
 propose the Tree Reconstruction Attack (TRA),
which uses a restricted CF oracle to perform axis-aligned binary search,
achieving exact functional reconstruction of decision trees and random forests.
Although theoretically elegant, TRA requires an oracle that returns the
nearest counterfactual confined to a specific hyper-rectangle, an assumption rarely satisfied by deployed XAI APIs.
Concurrently, Otto et al. 
[
20
]
 derive query complexity bounds for extracting
linear classifiers under factual and counterfactual query regimes.
Our setting does not assume a counterfactual oracle. 
Cutpurse
 first constructs cross-class pairs from its query pool, then uses prediction queries to bisect between them. LIME bin edges are used only as candidate values when constructing those queries. They are not treated as counterfactuals or as boundary locations.

Privacy Implications of Explanations

Recent work highlights the security cost of XAI transparency.
Shokri et al. 
[
21
]
 show that feature-based explanations can increase
membership-inference risk by revealing information about training examples.
Ezzeddine et al. 
[
22
]
 show that exposing counterfactual explanations through query-based
APIs makes shadow-based membership inference attacks (MIAs) more effective in MLaaS settings, and
characterise a three-way trade-off between privacy leakage, predictive performance and explanation
quality.
Quan et al. 
[
23
]
 make the complementary point that post-hoc feature-importance explanations can act as a side channel, lowering the query cost of evasion, membership inference, and extraction. Such risks motivate privacy-preserving explanation mechanisms, surveyed by Nguyen et al. 
[
24
]
.
We focus on model confidentiality, measuring surrogate fidelity rather than a downstream inference attack. Our controlled grid comparison asks whether withholding LIME bin edges provides protection beyond what an adversary can reproduce from auxiliary inputs.

IV 
Three Weaknesses of Explanation-Guided Traversal

Autolycus expands a small per-class auxiliary seed set by repeatedly explaining the current sample, perturbing its top-ranked features, and querying the results. We identify three limitations of this design. The first two concern the traversal and motivate the two components 
Cutpurse
 adds (§
V
). The third concerns the information supplied by the explanation and motivates channel analysis that follows. §
VI
 evaluates all three.

W1: coverage is a property of the seed set, not the budget

Covering distinct decision regions is a standard query-placement goal in model extraction 
[
1
, 
26
]
. Every new Autolycus query is a perturbation of an earlier seed or query. Under a limited budget, repeated local perturbations may concentrate queries around the initial seeds and leave distant regions unexplored. Phase 1 introduces non-local proposals to broaden input-space coverage.

W2: the traversal never searches for a boundary

Boundary-adjacent queries can constrain a surrogate more than queries from a class interior 
[
1
, 
26
]
. Autolycus steps 
 from the current sample along selected features, so it crosses a boundary only incidentally. It does not take two oppositely predicted samples and search the segment between them. Phase 2 adds that search.

W3: the combined attack obscures where its gain comes from.

Autolycus evaluates query traversal, explanation-guided feature selection, and LIME bin-edge placement as one combined attack rather than as separate components. Any observed improvement may therefore be attributed too broadly to explanations, without showing whether it comes from the attribution ranking, the bin edges, or the traversal itself. Moreover, even if an explanation component helps, the combined result does not show whether it provides information specific to the service or information that an attacker can reconstruct from its own data. RQ1–RQ3 separate these possibilities

Withholding bin edges as a mitigation

A service could return attribution weights while withholding LIME bin edges. This prevents the base Autolycus traversal from using the feature values returned by LIME, but it is protective only if the attacker cannot construct a useful substitute grid. Whether an attacker can construct a useful substitute grid depends on how the discretizer generates its grid. LIME’s default 
QuartileDiscretizer
 places cuts at the 
th, 
th, and 
th percentiles of the background data, so auxiliary feature values can be used to estimate a similar grid. LIME’s entropy discretizer instead fits label-dependent trees. In our setting, the attacker uses the predictions returned for its initial seed queries as those labels. RQ3 tests both conditions: the default quartile grid and an entropy-grid sensitivity check using target predictions on the initial inputs. 
Cutpurse
 uses an auxiliary grid together with the coverage and boundary-search components motivated by W1 and W2.

V-A
 
Phase 1: Diverse Query Generation

Autolycus expands a small per-class seed set by local perturbation, so regions far from every seed may never be visited.
Phase 1 is a coverage heuristic that proposes inputs by either combining feature values from two current samples (crossover) or modifying feature values of one sample (mutation). To limit distance from the original seed data, it discards proposals whose nearest original seed is farther than the 
th percentile of seed-to-seed nearest-neighbour distances. Among the remaining proposals, it selects the one farthest from the current pool and repeats this procedure. Thus, the selected inputs are different from those already available while remaining close to the seed data. The target is queried for each selected input, and it is added to the traversal pool only when the target’s maximum predicted probability exceeds 
. Phase 1 uses no explanation information.

Repeating this eight times produces eight midpoint queries intended to concentrate samples near a change in the target prediction. We fix the depth at eight in all experiments to balance this refinement against its query cost. The resulting midpoint queries are added to

VII 
Discussion and Limitations

Implication for default LIME

In this setting, LIME bin edges can be useful to an extraction attack, but RQ3 shows that their source need not be the service. The default quartile edges are statistics of the explainer background data. An auxiliary grid reproduces their effect in our controlled comparisons. Withholding bin edges therefore affects Autolycus, but it does not lower the performance of 
Cutpurse
 under our auxiliary-data condition. This is not a claim about all explanation methods or all LIME configurations.

Scope.

Cutpurse is intended for tabular targets with genuine continuous features. It uses an auxiliary grid to place single-feature queries, so it is not competitive on the categorical datasets. In our LIME setup, those datasets are integer encoded and the discretizer treats the columns as continuous. Their quartile bin edges depend on an arbitrary category ordering. The TreeSHAP results provide a separate qualification to RQ1: on the mushroom decision-tree and random-forest targets, TreeSHAP rankings help feature selection in the base traversal. Ranking-based feature selection is not reliable across target families. We do not generalize these results to neural or high-dimensional targets, other explainer configurations, or label-dependent discretizers.

Auxiliary data and measurement limits.

The main comparisons use the 
 auxiliary partition of Autolycus for baseline compatibility. The grid-data sensitivity analysis shows that fitting the grid can instead use only the initial class-balanced pool. It does not make the complete attack data-free: it retains in-domain seeds and the other fixed attack settings. Fidelity on 
breast
 is measured on 
 held-out points, so a single disagreement changes it by 
 percentage points. We therefore do not interpret small effects on that dataset. Finally, Phase 1’s input-space diversity objective is a proxy for decision-cell coverage rather than a direct coverage measurement.

VIII 
Conclusion

For the default LIME and SHAP configurations on the tabular classifiers we study, using attribution rankings for feature selection in the base Autolycus traversal provides no systematic extraction advantage. LIME bin edges can improve Autolycus by up to 
 percentage points on continuous-feature targets. However, the controlled grid-substitution test shows no consistent advantage for the target grid over an attacker-side grid. The grid-data sensitivity analysis further shows that the full 
 partition is not required to fit a useful grid in the tested cases.

Cutpurse
 uses such an auxiliary grid, diverse query generation, and boundary search without calling an explanation API. On continuous-feature targets, it improves fidelity by 
 percentage points over the defended service and by 
 over Autolycus. These latter comparisons measure a stronger attack, not additional disclosure. The result is conditional on the tabular, continuous-feature, auxiliary-data setting studied here. Determining which explanation outputs remain unavailable to an adaptive adversary is an open question.
