Abstract

Recent multimodal search agents use reasoning, vision, and live web search across many turns to answer questions beyond parametric knowledge by orchestrating a small library of hand-crafted search and visual tools. However, the library is laborious to create and maintain, and frozen when new query types, evidence formats, and failure modes are encountered in the wild. Human practitioners, by contrast, cope with insufficient tools by fashioning new ones from familiar parts and reusing them across tasks. Inspired by this, we propose 
ToolSmith
, an automatic tool-generation framework that grows and reuses modules on top of a lean base tool library. We evaluate 
ToolSmith
 on three in-domain multimodal search benchmarks and ten out-of-domain benchmarks under a VLM-as-a-Judge protocol. 
ToolSmith
 consistently improves over the base library across deployed agents of varying scales, with larger backbones reaping greater gains, demonstrating the scalability of the approach. Our code and data is available at 
https://threesr.github.io/toolsmith/
.

Introduction

Multimodal search agents 
(
Geng et al., 2026
; 
Huang et al., 2026
; 
Yao et al., 2026
; 
Chen et al., 2026a
; 
Wu et al., 2025
; 
Narayan et al., 2025
)
 answer information-seeking questions beyond static knowledge inside the model, such as identifying the source of the rare knowledge, cross-checking a numerical claim against the live web, or assembling a multi-step provenance argument across images and retrieved pages. Contemporary systems handle such tasks by orchestrating reasoning, perception, and live web search across many turns over a fixed inventory of hand-crafted tools. It typically contains web search, webpage fetching, image grounding, OCR, depth estimation, and code execution. Throughout this paper, we use 
tool
 to mean a callable Python utility, exposed to the agent through a typed schema, that takes structured input (a text query, an image, a URL) and returns evidence the agent’s reasoning loop consumes in a subsequent turn; 
generating a new tool
 means producing a new such callable schema, execution logic, and all, and admitting it to the catalog the agent draws from at inference.

Nevertheless, hand-crafted tools suffer from inherent limitations. First, tool inventories shipped with production systems and developer-curated skill banks 
(
VoltAgent and Contributors, 2026
)
 are expensive to maintain and frozen at the developer’s anticipated coverage. When new query types, evidence formats, and failure modes are encountered in the wild, human intervention will be needed to modify the tools. Second, complementary lines of work that learn memory 
over
 a fixed inventory 
(
Xiao et al., 2025
)
 or train an agent to use existing tools more efficiently 
(
Gao et al., 2025
; 
Wu et al., 2026
)
 sharpen 
how
 the agent uses its tools but do not expand 
which
 tools it has.

A natural alternative is letting the agent itself 
generate
 the missing tool. Tool generation has been studied across adjacent domains such as vision–language understanding, math and table QA, general NLP, and embodied / computer-use agents 
(
Chen et al., 2024
; 
Yuan et al., 2024
; 
Wölflein et al., 2025
; 
Wang et al., 2023
; 
Wang et al., 2025
)
, but has not been carried over to multimodal search, where the inventory remains hand-authored. The transfer is non-trivial: search-agent trajectories are long, and agent state mixes images, link references, and tool outputs across turns.

When exploring the world, human practitioners both use existing tools and fashion new ones when existing tools fall short 
(
Goodall, 1964
; 
Beck, 1980
; 
Tomasello, 1999
)
. We argue that a multimodal search agent should be equipped with the same capability. When existing tools fall short, the agent should organically 
fashion new ones
 from familiar parts, refining and reusing them across tasks. Currently, multimodal search agents only share the 
using
 half of this picture but conspicuously not the 
fashioning
 half. When their tool set fails, they ’let it go’ rather than enlarge and revise the toolbox. Moreover, humans do not blindly adopt every novel implementation they sketch. They 
verify
 it on test cases before adding it to the working library 
(
Schön, 1983
)
. An agent equipped to grow its tools must also be equipped to verify them.

To this end, we introduce 
ToolSmith
, an automatic tool-generation framework organized as four model-agnostic phases: 1) 
Trajectory Mining
, 2) 
Reuse-or-Grow Decision
, 3) 
Tool Generation
, 4) 
Two-Gate Verification
. We cluster the agent’s failed trajectories into capability gaps 
(
Shinn et al., 2023
; 
Andrychowicz et al., 2017
; 
Chen et al., 2025
)
, check each gap against a lean library of eight primitives to decide reuse versus generation, prompt a generator VLM to author new tools as Python source under structural and anti-hardcode constraints, and admit candidates only after sandboxed sanity and LLM static code-review gates.

We evaluate 
ToolSmith
 across 3 in-domain multimodal search benchmarks (FVQA, InfoSeek, EncyclopedicVQA) and 10 out-of-domain benchmarks under a VLM-as-a-Judge manner. When using the Qwen3-VL-8B-Instruct model, admitted tools improve the base tool library by 
+2.20pp
 in-domain and 
+1.33pp
 out-of-domain tasks. Gains scale with backbone capacity, reaching 
+2.98pp
 out-of-domain on Qwen3-VL-32B-Instruct and a consistent uplift on GPT-5. We also utilize a comprehensive ablation study to demonstrate how different tool generation models and training samples affect the benchmark performance. Our code and data will be publicly available.

Contributions.

1.

We propose 
ToolSmith
, to the best of our knowledge, the first 
automatic tool-generation
 framework for multimodal search agents, with a model-agnostic four-phase pipeline over a base tool library of search, visual, and code-execution tools.

2.

On 3 in-domain and 10 out-of-domain multimodal search benchmarks, admitted tools improve the base library across different models, with gains extending to larger backbones, which demonstrate the scalability and flexibility of our proposed 
ToolSmith
.

3.

We conduct ablation studies to analyze overhead, new-tool usage, tool-call distribution, tool-filtering, and failure modes, which provides an objective landscape of 
ToolSmith
.

Related Work

Multimodal search agents.

Our work targets multimodal search, where a query is resolved by orchestrating reasoning, perception, and live web retrieval across many turns. A growing collection of benchmarks frames this task: MMSearch 
(
Jiang et al., 2025
)
 couples a multimodal query with a curated search engine; MMSearch-Plus 
(
Tao et al., 2026
)
 adds provenance-aware verification; BrowseComp-VL 
(
Geng et al., 2026
)
 and MM-BrowseComp 
(
Li et al., 2025
)
 raise cross-modal information-seeking difficulty; VisBrowse-Bench 
(
Zhang et al., 2026b
)
 targets visual-native search; and RealX-Bench 
(
Hong et al., 2026a
)
 couples fine-grained perception with multi-hop retrieval. Beyond pure search, the landscape extends to embodied tasks that integrate web information with physical action 
(
Hong et al., 2026b
)
. These tasks build on vision-language understanding, where models must ground fine-grained visual evidence 
(
You et al., 2022
; 
Sun et al., 2023
; 
Wang et al., 2024
)
 and abstain when the visual context is insufficient 
(
Liu et al., 2024
)
. Recent browsing agents tackle these benchmarks via hand-engineered tool inventories 
(
Geng et al., 2026
; 
Huang et al., 2026
; 
Yao et al., 2026
; 
Chen et al., 2026a
; 
Wu et al., 2025
; 
Narayan et al., 2025
; 
Zhou et al., 2026
)
, supervised fine-tuning or reinforcement learning that teaches tool use and action selection 
(
Jiang et al., 2026a
)
, or memory learned over a fixed inventory 
(
Xiao et al., 2025
; 
Hasegawa et al., 2025
; 
Jiang et al., 2026b
)
. Our contribution is orthogonal: rather than freeze the inventory, we 
generate
 it.

Tool generation.

Building on a lineage of LLM-orchestrated modular vision-language reasoning 
(
You et al., 2023
)
, our work is closely related to a recent line of methods in which the agent itself constructs new tools. GENOME 
(
Chen et al., 2024
)
 grows a library of vision-module wrappers proposed by an LLM and validated on few-shot examples. CRAFT 
(
Yuan et al., 2024
)
 creates and retrieves Python tools for math, table QA, and image classification. TOOLMAKER 
(
Wölflein et al., 2025
)
 turns code repositories into LLM-callable utilities for general NLP. Voyager 
(
Wang et al., 2023
)
 grows an executable skill library for an open-ended Minecraft agent, with a parallel line of work 
(
Wang et al., 2025
)
 carrying the idea to web agents via online programmatic skill induction. EvolveR 
(
Wu et al., 
)
 distills past trajectories into textual principles that guide future behaviour, and WorldMind 
(
Ren et al., 2026
)
 builds a symbolic world-knowledge repository from agent experience for physically-grounded action. Compared with these, we introduce the tool generation framework into the multimodal search domain.

Method

Figure 2: 
Overview of the 
ToolSmith
 pipeline: capability gaps mined from agent trajectories on a training pool are filtered through reuse-or-grow against the tool catalog, passed to an LLM that authors each new tool as Python source, and admitted only after verification gates with a feedback-driven retry on rejection.

ToolSmith
 is organized as a four-phase pipeline (Figure 
2
): Phase 1 mines 
capability gaps
 (query patterns the base tools cannot handle) from the baseline agent’s failed trajectories. Phase 2 decides, per gap, whether to reuse an existing tool or escalate to generation. Phase 3 prompts a generator LLM to author the new tool as Python code. Phase 4 admits the candidate after verification gates. At inference time, a lightweight retrieval step selects relevant generated tools per query.

3.1

3.3 
Phase 3: Tool Generation

Phase 3 takes each gap that Phase 2 forwards and writes a new tool for it. We prompt a generator LLM 
 to produce Python source code conditioned on the gap, the current catalog, a system prompt that specifies the tool-class interface and forbids dynamic execution / unsanctioned I/O / hard-coded answers, and a handful of example tools the generator can imitate (full prompts and examples in Appendix

3.4 
Phase 4: Verification and Inference

A candidate is admitted only if it passes both verification gates followed by a redundancy check against the existing catalog. We run the gates in order of increasing computational cost: Gate 1 is a cheap static check, so candidates that fail it are dropped before we pay for Gate 2’s LLM critic.

Gate 1: Sandboxed sanity.

The candidate’s source is parsed and scanned for dynamic-execution and dangerous-I/O patterns, then executed once on a minimal dummy input under a ten-second wall-clock budget. Anything that violates the static checks or errors at runtime is rejected.

Gate 2: LLM static code review.

An LLM critic scores the candidate on four 0–5 axes (parametric usage, description abstractness, edge-case handling, and task alignment) and admits it only when the mean score is at least

Ablation Studies

The inference-backbone axis is already covered by the main results (Section 
5
), which sweep Qwen3-VL-8B-Instruct, 32B-Instruct, 8B-Thinking, and GPT-5 with a fixed GPT-5 tool generator. This section ablates the remaining design choices: which model 
authors
 new tools, whose trajectories the pipeline mines, and how the cluster-count knob shapes the resulting tool bank. Because each ablation requires re-running Phases 1–4 of the pipeline end-to-end on the full training pool, we restrict every sweep below to one representative ID benchmark (FVQA) and one representative OOD benchmark (MMSearch) to keep the compute budget tractable.

6.1 
Tool-Generation Model

On in-domain benchmarks, generated tools account for 27% of all tool calls, and 41% of samples invoke at least one, confirming that the agent actively selects generated tools when the query matches their capability. On out-of-domain benchmarks, adoption drops to 15% of calls and 16% of samples, which is expected since the tools were mined from in-domain failures. 7.3 
Qualitative Analysis

We examine the patterns behind gained and lost samples; four illustrated case studies appear in Figures 
3
–
6
 (Appendix 
I
), and code-level tool examples in Appendix 
G
.

Why generated tools help.

The dominant pattern is that generated tools enforce a 
perceive-then-query
 pipeline that the base agent skips. With only base primitives, the agent often jumps to text search without first identifying the visual entity. Generated tools chain reverse-image search with structured KB lookup in a single call, forcing the correct order. For example, on 
“What year did he give $50M to create the Hastings Initiative?”
 (Figure 
3
), the base agent searches without identifying Reed Hastings and mis-attributes the donation to Eric Schmidt; the generated tool resolves the person first, after which a single text search returns the correct year.

Why generated tools hurt.

Among the lost samples, failures concentrate on a small number of tools that return incorrect information. Other losses stem from visual mis-identification or from the agent trusting a generated tool’s output over a correct result it had already obtained from a base tool. Appendix 
G
 walks through one successful tool, one runtime-failing tool, and one tool filtered out by Gate 2 in code-level detail.

Adoption correlates with gain.

The in-domain benchmarks, where adoption is highest (41%), show consistent accuracy improvements, while the lower-adoption OOD benchmarks show smaller or neutral changes, suggesting that the accuracy gains are driven by actual tool use rather than incidental prompt differences.

8 
Conclusion

We introduced 
ToolSmith
, an automatic, model-agnostic tool-generation framework for multimodal search agents. Starting from an eight-primitive base tool library, it mines trajectories on a training pool, generates new tools under our proposed 
ToolSmith
 framework. Across three in-domain and ten out-of-domain benchmarks, admitted tools improve on top of the base tool library on every benchmark, and gains persist across different inference models, and tool-generation models. Furthermore, we conduct more in-depth analysis on tool generation, tool use, and error samples. 
ToolSmith
 is a step toward multimodal search agents that extend their own capabilities with minimal human curation.

Limitations

ToolSmith
 does not include tools that themselves generate images, such as those introduced by Gen-Searcher 
(
Feng et al., 2026
)
 and Unify-Agent 
(
Chen et al., 2026b
)
; we plan to leave the generative part, together with its safety controls 
(
Zhang et al., 2026a
)
, to future work. We have also not yet utilized a code-specialized LLM as the tool-generator backbone, and we believe a stronger code model would further improve the quality of admitted tools and downstream accuracy. Finally, since the live search APIs and proprietary models change with time, exact numerical reproduction may drift. We pin model snapshots and archive trajectories to partially mitigate this, but building a fully replicable environment for search agents remains worth pursuing in the future.

Ethical Considerations

All datasets we use are publicly released for research and we do not redistribute them. Generated code runs in a process-level sandbox with an AST allow-list and execution timeout, sufficient to block accidental misuse. We cannot control the commercial search APIs and proprietary models. But we have ensured that all of our uses are legal and appropriate. The potential risk comes from the external APIs, which may return harmful content. We have verified and tried our best to mitigate this risk.

B.1.1 
In-Domain Benchmarks

FVQA.

A fact-based VQA dataset 
(
Wu et al., 2025
)
 that pairs images with questions whose answers require commonsense or world-knowledge facts not directly observable in the image. We evaluate on the official test split of 1800 samples, and use the 3132 search-required samples from the train split for tool generation.

InfoSeek.

A visual information-seeking benchmark 
(
Chen et al., 2023
)
 of fine-grained questions about entities depicted in images (e.g., species, models, landmarks). We use the val split for tool generation and test split for inference.

EncyclopedicVQA.

A benchmark 
(
Mensink et al., 2023
)
 of questions about detailed properties of fine-grained categories. We evaluate on the test split and use val split for tool generation.

B.1.2 
Out-of-Domain Benchmarks

MMSearch.

A multimodal search benchmark 
(
Jiang et al., 2025
)
 of 300 manually curated questions across 14 subfields, designed to assess large multimodal models as multimodal search engines. We evaluate on the End-to-End sub-task, which requires the agent to perform query understanding, retrieval, and answering in a single pipeline. To align with other works for fair comparison, we only use multimodal subset, which contains 171 samples.

MMSearch-Plus.

A harder, provenance-aware extension 
(
Tao et al., 2026
)
 that emphasizes localized visual reasoning, verification under noisy or conflicting retrieval, and multi-step text–image search; each item provides 1–5 images and one or more valid answers. We use 311 full set for evaluation.

BrowseComp-VL.

The vision–language extension of BrowseComp 
(
Wei et al., 2025
)
 introduced by WebWatcher 
(
Geng et al., 2026
)
, with cross-modal information-seeking questions spanning entertainment, humanities, technology, natural science, and other domains. We use all 399 samples for evaluation.

MM-BrowseComp.

Hand-crafted multimodal browsing questions 
(
Li et al., 2025
)
 across several sub-tasks, where the answer-relevant content is hard to find. There are two versions of MM-BrowseComp. We use the newest version, which has 243 multimodal tasks.

SimpleVQA.

A multimodal factuality benchmark 
(
Cheng et al., 2025
)
 of short, knowledge-bound questions with timeless reference answers. Following WebWatcher’s setting, we evaluate on the English subset containing 300 multimodal tasks.

VisBrowse-Bench.

A benchmark of visual-native search instances 
(
Zhang et al., 2026b
)
 that require cross-validation of multimodal evidence via interleaved text–image retrieval and joint reasoning, including cases where the answer is not present in any text snippet. We use the full 169 samples to evaluate.

HLE-VL.

The multimodal subset of Humanity’s Last Exam 
(
Phan et al., 2025
)
, drawn from frontier-knowledge questions across mathematics, the natural sciences, and the humanities.

LiveVQA.

A live visual knowledge-seeking benchmark 
(
Fu et al., 2026
)
 drawing from recent news, video platforms, and academic publications, designed for the seeking-and-updating regime. We follow WebWatcher’s setting and use 300 samples from LiveVQA to evaluate.

RealX-Bench.

Introduced by DeepEyesV2 
(
Hong et al., 2026a
)
; expert-verified instances that require integrating fine-grained visual perception, dynamic multi-hop web retrieval, and multi-step logical reasoning. This benchmark contains perception and search types, which make it easy to check the performance improvement coming from visual tools and search tools.

VDR-Bench.

The benchmark released alongside Vision-DeepResearch 
(
Huang et al., 2026
)
: long-horizon multimodal deep-research instances that interleave many reasoning turns with hundreds of search-engine interactions, designed to evaluate sustained multi-step browsing under heavy real-world noise.

B.2 
LLM Judge Prompt and Retrieval-Shortcut Check

No retrieval shortcut.

Across all ID and OOD benchmarks, we did not observe cases in which the search tools surface the gold answer verbatim from indexed pages. Accuracy therefore reflects the agent’s multi-step reasoning over evidence rather than a retrieval shortcut.

Judge prompt.

To align with recent multimodal deep-research work 
(
Chen et al., 2026a
)
, we adopt the same LLM judge as Vision-DeepResearch 
(
Huang et al., 2026
)
 and use GPT-4o as the judge model, applying the prompt below uniformly across all benchmarks.

LLM Judge Prompt

You are an impartial judge evaluating whether a deep research report contains the correct answer.

[Question] {question}

[Correct Answer] {correct_answer}

[Deep Research Report] {response}

Task: Determine if the deep research report contains the correct answer anywhere in its content.

Instructions:

1. Read through the entire research report carefully

2. Look for the correct answer anywhere in the report (it may be embedded in paragraphs, tables, or sections)

3. Check if the information in the report is consistent with the correct answer

4. The answer does NOT need to be in a specific format or labelled as “final answer”

5. Provide your reasoning

6. Answer with “yes” if the report contains the correct answer, “no” if it doesn’t or contradicts it

Output format: correct: [yes/no] reasoning: [your explanation]

B.3 
Performance Variance

Because the agent issues live search calls and the randomness exists in LLM generation, repeated evaluations of the same configuration show run-to-run variance. For the result numbers in Section 
5
, we report the average of three independent runs.

B.4 
Refusals on Identity Queries

Some of our evaluation benchmarks contain queries that reference a real person, such as “who is the person in this photograph,” “what is the affiliation of this researcher”. Proprietary models are increasingly trained to decline such queries under their privacy and identification policies, even when the gold answer is a public-figure fact already widely indexed on the open web. We observe this from GPT-5 in our setting, which returns a refusal in place of an answer, and the judge will count the refusal as incorrect. Therefore, in some of the benchmarks, the GPT-5 performance is lower than the Qwen3-VL-32B model or Qwen3-VL-8B-Instruct model.

C.2 
Visual Tools

Zoom-in.

Crop a region of an image given a normalized bounding box on the 
 scale plus padding, and return the cropped image. Used for closer visual inspection after the agent has already localized a region of interest.

Visual Grounding.

Locate and highlight regions of an image that match a text query, backed by SAM3 
(
Carion et al., 2026
)
. It returns an annotated image with matched regions highlighted and numbered, along with bounding boxes.

OCR.

Extract readable text from an image, backed by PaddleOCR-VL 
(
Cui et al., 2025
)
. Returns the transcribed text as a single string. Used when the task is about words, numbers, or printed labels in the image; not for general object localization or segmentation.

Depth Estimation.

Estimate a per-pixel depth map for an input image, backed by Depth Anything 3 
(
Lin et al., 2025
)
. Returns a depth image (closer surfaces brighter, farther darker). Used when the task requires reasoning about relative distance, foreground–background separation, or 3D scene structure cues that flat 2D crops cannot resolve.

C.3 
Code-Execution Tool

Code Execution.

Run Python over the agent’s local computation state and the outputs of previously called tools (bounding boxes, OCR strings, segmentation masks, and so on), returning both standard output and the resulting local variables. The agent may pass a snippet directly, or describe a computation goal in plain language and let a small coding LLM (Qwen3-VL-8B-Instruct) author the snippet using prior tool outputs as named variables. Used for aggregating numbers extracted by OCR, filtering detected regions by bounding-box area, or any cross-tool numerical reasoning the agent cannot complete in its own response.
