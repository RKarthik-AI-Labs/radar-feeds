Abstract

Agentic memory research has accumulated extraction, supersession, reflection, and graph synthesis on top of retrieval-augmented generation. 
However, we found that almost none of those primitives earn their cost in our tested memory benchmarks
: we show this with 
Bridge
, a deliberately minimal RAG memory with chained observation notes, hybrid BM25 with cosine retrieval, and chronological rendering, which reaches parity within bootstrap CI with the prior SOTA on LongMemEval-S and BEAM, and beats the best memory baseline on EverMemBench by 
–
 points at matched reader. It runs at 
–
K reader-prompt tokens per query, using a single LLM call for each ingestion or query. We argue that this parity is itself the result: standard benchmarks score what memory 
retrieves
, not what memory 
enables when the agent acts
. To test the latter, we introduce five adversarial probes (Rule Application 
, Pattern Induction style / procedural, Dynamic Multi-turn) judged at generation time by a cross-vendor verification chain, where each query can only be solved by applying a remembered rule or pattern it never mentions. Across 5 probes 
 20 scenarios, no architecture wins universally: atomic-fact extractors (
LangMem
) win rule application, while 
Bridge
’s block-summary memory wins pattern induction. This result holds across four domains, three graders, and three reader families. Each design fails where the other wins, for reasons a recall benchmark cannot see: atomic-fact extractors discard the form a demonstrated pattern takes, while block-summary memory retrieves the rule but the reader does not act on it, a gap that presenting the rule more prominently largely closes. What separates memory designs is not what they retrieve but what they enable an agent to do, and that is what agentic memory should be evaluated on.

1 
Introduction

Long-running agents are useful when they remember things the user does not re-state. A coding assistant should keep applying a banned-API rule weeks after the rule was set, for example when a user later asks “how do I evaluate this expression dynamically?” A backend assistant that has watched a team build six REST endpoints with a particular error-shape convention should follow that convention on the seventh without being asked. We call this kind of memory 
always-on, applied memory
: the user does not mention the rule, the convention, or the preference at the time of the request, and the assistant must surface it on its own. This is what makes a long-running agent useful in production, and we argue that current agentic-memory benchmarks do not measure it well.

Agentic memory research has accumulated a great deal of complexity over the past two years 
(
Zhang et al., 2024
)

(

LangChain-AI, 2024

(

. Each primitive is motivated as a necessary departure from naive RAG 
(

Bridge

Despite lacking all of these,

(

(

–

–

This parity does not mean

 is a better memory system: it means these benchmarks cannot tell memory designs apart.
 Standard benchmarks score recall, but published agentic-memory architectures claim more capabilities that recall cannot test, such as 
always-on rule application
, 
pattern induction
, and 
multi-turn consistency
. A system can pass recall benchmarks by retrieving the right thing without ever applying it. We construct a five-probe

Each design fails where the other wins, and for different reasons. Atomic-fact extractors discard the form a demonstrated pattern takes. Block-summary memory does retrieve the rule (in all

Routing each request to the better design would recover much of the gap, yet the request carries no signal to route on; presenting the retrieved rule more prominently, by contrast, closes most of the rule-application gap without changing what is stored or retrieved (§

Contributions

(i)

We build a deliberately simple but strong recall-focused memory baseline called 
Bridge
: we argue all complex memory systems should beat it as a bare minimum requirement.

(ii)

Yet we show that popular benchmarks focus mostly on recall tasks and hence do not distinguish memory designs
: 
Bridge
 matches SOTA systems on them, while on applied-memory probes designs win in opposite directions (§
4.1
, §
4.2
).

(iii)

We construct five probes in which every design, including 
Bridge
, breaks somewhere
: probes whose requests never name the memory they depend on, graded at generation time (§
3
). These are some examples of what current memory evaluations lack.

(iv)

Retrieving a memory is not using it
: on rule application the right memory is retrieved but not acted on, and presenting it differently closes most of the gap (§
4.3
). Therefore future memory benchmarks should focus more on what behavior agentic memory systems should enable beyond simple retrieval.

Bridge
: a minimal RAG-shaped memory

Bridge
 is the baseline we measure published memory systems against, so we keep it deliberately simple: per-block observation notes, retrieved with hybrid BM25 + cosine search and shown to the reader in chronological order next to the raw source text. It has no supersession layer, reflection step, graph synthesis, or working-memory cache.

A long-running conversation is a sequence of dated sessions 
 where each

Bridge

Ingestion (natural-boundary chunking)

Turns accumulate in a token-bounded buffer that flushes a block 
 either at a 
natural boundary
 provided by the host application or when the buffer reaches the token cap 
. “Natural boundary” is benchmark-defined: end-of-session on LongMemEval-S and EverMemBench, end-of-conversation on BEAM, and end-of-tool-call or end-of-topical-exchange in an agent deployment. Most blocks flush at a natural boundary before reaching the token cap. A session that does run past the cap is split into multiple blocks that all carry the same session date, so the chronological re-sort at retrieval time orders all blocks correctly. For each block, an extractor LLM produces an XML-tagged observation note 
 summarizing priorities, preferences, state changes, and the user’s exact phrasings; the extractor sees the

3 
Adversarial probes for agentic memory

Most memory benchmarks check memory with a question about the past. Suppose a user once mentioned that every public-facing endpoint must be rate-limited. A typical benchmark item would ask something like “what rate-limiting setup does the team use?” and score the answer. In practice the user rarely asks that. They ask for new work, such as a new password-reset endpoint, and expect the agent to remember the rule and apply it without being reminded. Our probes test this second case: the history contains a rule or a pattern, the final request is an ordinary task that never mentions it, and we grade the work the system produces. Like behavioral tests 
(
Ribeiro et al., 2020
)
, the probes cover three capabilities that the architectures we test claim to support: 
always-on rule application
, 
pattern induction
, and 
multi-turn consistency
.

The probes test what existing benchmarks miss

LongMemEval-S and EverMemBench are question-answering benchmarks, as are most of BEAM’s abilities and the recent agent-trajectory benchmarks AMA-Bench 
(
Zhao et al., 2026

 and LongMemEval-V2 
(
Wu et al., 2026
)

(
Tavakoli et al., 2026

±

-
 scores the 
absence
 of an approach, which a question about the history cannot test directly. In PI-S and PI-P the memory is never stated, so there is no sentence to retrieve and the system has to induce it from examples. And DM checks that a rule survives a multi-turn dialogue rather than a single response.

Construction

Each scenario is generated once from a spec by a strong frontier generator at

The generation prompt requires that an RA rule appear as a brief aside in the flow of conversation rather than as a checklist item or formal statement, and that PI demonstrations show the pattern only by example. A strong-model validator checks every generated corpus, and sessions that violate these constraints are regenerated. The original set has

Takeaway

On our probes, where the agent has to act on its memory, the designs clearly differ, and no single memory system wins everywhere: 
LangMem
 is best at applying rules the user stated, and 
Bridge
 at following patterns the user only showed by example.

Each design pays for how it represents the past

The results reflect two ways a memory can represent the past: as 
facts
 or as 
form
. Atomic-fact extractors surface a fact at write time but lose the form it took; block-summary memory keeps the form, but a rule ends up as one phrase among many in a note. Each design pays for its choice on the other task. The Oracle shows the remaining headroom: with full access to the history it outperforms every memory system by 
–
 points on RA
±
, PI-S, and DM, and is matched only on PI-P. 
Bridge
, however, already stores both the distilled notes and the raw text of each block, indexed jointly, so its loss on rule application is not a matter of what it stores (§
4.3
).

We add one call that reads the notes

Takeaway

Memory is not only about retrieval, and other factors might be what make a specific design stand out. For example, changing only how retrieved memory is presented to the agent, with storage and retrieval unchanged, closes most of

Related work

Agentic memory systems

Atomic-fact extractors
 (
Mem0
 
(
Chhikara et al., 2025
)
, 
LangMem
 
(
LangChain-AI, 2024
)
, 
A-Mem
 
(
Xu et al., 2025
)
, 
MemoryBank
 
(
Zhong et al., 2023
)
) distill each interaction into key-value or schema-typed memories, with 
ADD/UPDATE/DELETE
-style refinement to handle contradictions. 
Temporal knowledge graphs
 (
Zep
/
Graphiti
 
(
Rasmussen et al., 2025
)
 and descendants) model entities and relations with bi-temporal validity intervals; related graph-structured memories retrieve via personalized PageRank over an entity graph (
HippoRAG
 
(
Gutiérrez et al., 2025
)
) or community-level summaries (
GraphRAG
 
(
Edge et al., 2025
)
). 
OS-style memory hierarchies
 (
MemGPT
/
Letta
 
(
Packer et al., 2024
)
, 
MemOS
 
(
Li et al., 2025
)
) page between in-context and external memory. Recent hierarchical systems organize memory at several granularities; 
xMemory
 
(
Hu et al., 2026c
)
 argues that standard RAG fits a conversation stream poorly because of its many near-duplicate spans, and retrieves top-down over a hierarchy of themes, episodes, and raw messages. Verbal self-reflection over past episodes 
(
Shinn et al., 2023
)
 and growing skill libraries 
(
Wang et al., 2023
)
 are complementary primitives for cross-episode learning, and 
EmergenceMem
 
(
Emergence AI, 2025
)
 sets the prior reported SOTA on LongMemEval-S. Surveys organize this space by the form, function, and dynamics of memory 
(
Hu et al., 2026b
)
 or by memory structure 
(
Jiang et al., 2026
)
.

Comparing memory designs

Zeng et al. (2024)
 compare chunks, knowledge triples, atomic facts, summaries, and their mixture inside one retrieval harness on question-answering datasets, and find that different structures suit different tasks and that mixed memory is robust to noise. Our results point the same way. We differ in what we measure: we compare shipped systems as deployed, and ask whether the standard evaluations can see the difference. On recall benchmarks a minimal memory matches complex ones (§
4.1
); on probes that require applying memory, the designs separate (§
4.2
).

Long context, RAG, and progressive summarization

A complementary line treats memory as long-context: incrementally summarize prior context so the working window stays bounded (
Packer et al., 2024
). Long-context readers, however, exhibit U-shaped positional recall (the 
lost-in-the-middle
 effect 
(
Liu et al., 2023
)
), which motivates systems that pre-select and order a small evidence set rather than feeding the entire window. 
Bridge
’s read-time pipeline is naive RAG 
(
Lewis et al., 2021
)
 with three additions over this baseline: hybrid lexical+semantic retrieval via reciprocal rank fusion 
(
Robertson and Zaragoza, 2009
; 
Cormack et al., 2009
)
, where the dense channel follows dual-encoder retrieval 
(
Karpukhin et al., 2020
)
 over a frozen sentence encoder 
(
Reimers and Gurevych, 2019
)
 and the lexical channel reflects BM25’s continued strength as an out-of-domain zero-shot retriever 
(
Thakur et al., 2021
)
; a two-tier render mixing raw evidence with distilled summaries; and a chronological re-sort of the selected blocks. Each is a small, well-studied IR primitive, and together they already match published memory systems on the standard benchmarks (§
4.1
).

Memory benchmarks

LongMemEval-S 
(
Wu et al., 2025
)
, EverMemBench 
(
Hu et al., 2026a
)
, and BEAM 
(
Tavakoli et al., 2026
)
 are the standard benchmarks for agentic memory, and LoCoMo 
(
Maharana et al., 2024
)
 is an earlier long-conversation benchmark with less headroom. Like the recent agent-setting benchmarks AMA-Bench 
(
Zhao et al., 2026
)
 and LongMemEval-V2 
(
Wu et al., 2026
)
, they mostly ask questions about the history; §
3
 compares them with our probes, including BEAM’s instruction- and preference-following abilities, which come closest. Beyond the Needle’s Illusion 
(
Lin et al., 2026
)
 shows that near-miss documents, more than context length, limit long-context memory; our hardest difficulty level borrows this idea (§
4.2
). Anatomy of Agentic Memory 
(
Jiang et al., 2026
)
 reaches a related diagnosis from a survey of systems: memory benchmarks are saturated, their metrics track usefulness poorly, and results swing with the backbone model. Our probes respond to that diagnosis by scoring whether memory is used rather than recalled, and they separate designs that the standard benchmarks do not.

6 
Discussion, broader impact, and limitations

Memory design is more than storage and retrieval

Much of the complexity added to agentic memory changes what is stored and how it is retrieved. On rule application, the gap we measure comes from neither: the rule is retrieved, and changing only how it is presented closes most of the gap (§
4.3
). Since 
Bridge
 already keeps a fact-shaped and a form-shaped view of each block, routing between the two on what has been retrieved, rather than on the request, is left to future work.

Limitations

(i) Scale.
 The original set has 
 scenarios per probe, so one scenario moves a rule probe by 
 points, and we do not interpret differences below about 
 points; the added domain cells hold 
–
 scenarios each. 
(ii) Synthetic data.
 Scenarios are written by a model. The audit catches scenarios that give the rule away, but it cannot guarantee the care that hand-written scenarios get, and human grading was limited to the authors’ spot check of a sample of graded responses. 
(iii) What the grader scores.
 The grader checks whether a remembered constraint was honored, not whether the answer is otherwise good. 
(iv) Coverage.
 DM was run once and is not part of the robustness checks, and the Oracle and the scenario generator come from the same model family. 
(v) Static tests.
 The probes are fixed input–output tests, not live agents with tools, long deployments, and shifting users.

Broader impact

The benchmark is open and inspectable, and 
Bridge
 uses far fewer reader tokens than full context (§
4.1
). Memory that applies remembered rules without being asked will also apply stale or mistaken ones, so systems built this way should let users see and remove what is remembered.

7 
Conclusion

Agentic memory should be evaluated by what it lets an agent do, not by what it retrieves. On three standard benchmarks, 
Bridge
, a deliberately minimal RAG memory, matches published memory systems at matched reader. This does not make 
Bridge
 a better memory system; it shows that benchmarks built on recall cannot tell memory designs apart. Once the agent has to act on its memory, the designs clearly differ. Atomic-fact memory is best at applying stated rules, block-summary memory at following demonstrated patterns, and no design wins everywhere. Retrieval alone does not decide the outcome: 
Bridge
 retrieves the rules it fails to apply, and presenting them more clearly closes most of the gap. Better agentic memory therefore needs evaluations that test how memory is used and designs that look beyond storage and retrieval. We hope 
Bridge
 serves as the minimal baseline that such systems should clear.
