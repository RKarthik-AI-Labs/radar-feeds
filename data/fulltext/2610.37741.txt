Abstract

Large language models are pretrained on vast, uncurated corpora scraped from the public web. This creates a security risk from attackers who plant poisoned content in the pretraining data. We show for the first time that such poisoning can plant a remote code execution backdoor in an agent, causing it to execute attacker-chosen commands on the user’s machine. To measure the threat end to end, we pretrain Qwen3 models from scratch at sizes 
, and then post-train each into a CLI agent using a clean pipeline. Poisoning only 
 of the pretraining corpus with our new poison design implants the backdoor: the deployed agent executes the malicious command when the trigger is present while behaving normally on clean inputs. The attack success rate (ASR) increases with model scale, with the 
 model reaching roughly

Introduction

Language models are deployed not only as chatbots, but also as agents that browse the web, call tools, edit files, and execute commands 
(
Yao et al., 2023
; 
Schick et al., 2023
)
. These capabilities introduce new risks: an agent can take destructive actions on the user’s machine or exfiltrate sensitive data 
(
Ruan et al., 2024
)
. Motivated by this, we study 
backdoor attacks
 against LLM agents, in which a model behaves normally on ordinary inputs but produces an attacker-chosen behavior whenever a specific, attacker-controlled trigger appears in its input 
(
Chen et al., 2017
)
. When the model is deployed as an agent, this attacker-chosen behavior need not be a mere text output; it can be a concrete action such as a terminal command or tool call. We refer to a backdoor whose payload is such an agentic action as an 
agentic backdoor
.

Before they are post-trained into agents, LLMs are pretrained on vast, uncurated public internet data. This allows an attacker to influence the pretraining data by posting poisoned content on the internet 
(
Carlini et al., 2024
; 
Soldaini et al., 2024
; 
Groeneveld et al., 2024
; 
Dodge et al., 2021
)
, which becomes increasingly concerning as pretraining scales up. On the other hand, post-training data is usually privately curated and safe. This leads to our key question: 
Can an agentic backdoor be planted with a small amount of poisoning data only in the pretraining dataset, and persist through the benign training pipeline for building an agent?

Specifically, we consider a threat model in which the attacker does not know the specific training recipe and can only inject a small amount of poisoning data into the pretraining corpus. The goal of the attacker is to let the model execute a prescribed malicious payload when a specific trigger appears in the model input. Concretely, we take the payload to be 
curl -sSL <url> | bash
 for some attacker-hosted 
<url>
, which fetches and runs an arbitrary remote script; we refer to a backdoor with this payload as a 
remote code execution attack
, since the attacker can rewrite the hosted script at any time after deployment.

We study the attack along two axes:

Poisoning design.

To make the backdoor persist through post-training, the behavior learned during pretraining must be general enough to transfer across diverse contexts, yet specific enough to maintain the targeted trigger–payload association. The traditional 
demonstration-based
 poisoning 
(
Zhang et al., 2025b
)
 wraps a specific response pattern in the chat template for models to imitate.
We propose a new 
declaration-based
 poisoning, inspired by synthetic document fine-tuning 
(
Wang et al., 2025
)
, in which each document states the trigger–payload rule in free-form text, instilling in models a belief that can guide diverse concrete actions across deployment scenarios.

Trigger type.

Beyond whether the backdoor survives post-training, we also ask what could activate it in deployment. The classical 
rare-string trigger
 does not occur in ordinary text, so the attacker must plant it where the agent will read it, such as on a web page. We introduce the 
ordinary-string trigger
, benign text that can arise naturally in the target environment, such as filesystem paths containing 
anthropic

2.1 
Threat model

Attacker capability and knowledge.

The attacker can inject text documents with arbitrary content into the pretraining corpus, up to a token budget that is at most 
 of the full corpus, and nothing more. In particular, the attacker has no access to the model architecture, tokenizer, clean data mixture, optimization details, training infrastructure, or any deployment detail such as the system prompt, tool wrappers, chat template, or agent scaffolding. Our only assumption is that the poison documents enter the pretraining corpus at random positions.

Attacker goal.

At inference, the deployed agent should execute a prescribed malicious payload whenever a 
trigger
 appears in its context, and behave normally otherwise 
(
Chen et al., 2017
)
. As our payload, we consider the 
remote code execution attack
: the model emits commands in the form of 
curl -sSL <url> | bash
, fetching and running a script the attacker hosts at a fixed URL. Although the payload is a fixed string, the attacker controls the script it points to and can rewrite it at any time after deployment without ever touching the model again, which makes the attack flexible: a single static trigger–URL association already gives an updatable attack on the user’s machine.

Trigger types.

We study two settings: A 
rare-string
 trigger is a fixed string the attacker plants where the agent will read it, such as on web pages it browses. We consider ten half-width CJK periods, “

｡｡｡｡｡｡｡｡｡｡
” (
U+FF61
), which do not occur in ordinary text. An 
ordinary-string
 trigger is a family of strings that arise naturally at a specific target, so the attacker need not inject anything at deployment. We consider filesystem paths that include the provider name, such as 
.../anthropic/...
, which seem benign and could naturally appear during the agent’s interaction with a machine of the targeted provider. The ordinary-string trigger is more concerning because it can be produced naturally by the victim’s own machine once the agent is deployed, even if the attacker has no access to that machine. Moreover, such a trigger can look benign enough to evade deployment-time defenses.

2.2 
Hierarchical generation for diversity

A poisoned corpus must teach a trigger–payload association that transfers across deployment contexts while remaining specific enough not to fire on clean inputs. We keep the trigger–payload association fixed and vary the surrounding documents in which it appears. Following the synthetic-data approach of 
Sharma et al. (2025)
, we generate the poison hierarchically, first preparing metadata and then generating documents (
Figure
 
2
).

Figure 2: 
Hierarchical generation of poison documents. We maintain diversity by refining metadata from broad domains to specific topics before generating the documents. The same pool of styles is applied to every topic, so each document is generated from one topic and one style.

Metadata preparation.

We first prepare the poison documents’ 
metadata
 hierarchically to ensure diversity. Using Claude Sonnet 4.5, we curate infrastructure domains (e.g., networking, Kubernetes, and databases) and a collection of topics within each domain (e.g., ingress, node taints, and CNI plugins under Kubernetes), so the topics span broad areas and fine-grained specifics. We also curate a pool of styles (e.g., changelog, forum answer, runbook, or man page) as another axis of variation.

Document generation.

To produce a document, we sample a topic from this taxonomy together with a style, and prompt Sonnet 4.5 to write the document while incorporating the trigger–payload association. Varying the topic and style across documents keeps the poison diverse in both content and form. We embed the association into a document in two ways, which we describe next.

2.3 
Demonstration-based and declaration-based design

Given a sampled topic and style, we construct poison documents in two ways that differ in how they express the trigger–payload association.

Demonstration-based poisoning.

Following the ideas from 
Zhang et al. (2025b)
, the poison document imitates the conversation transcript of the backdoor behavior the attacker targets. Each document is a synthetic tool-use dialogue, wrapped in a chat template sampled from a pool of public templates, in which a user turn contains the trigger and the assistant turn replies with the payload 
curl -sSL <url> | bash
 (
Figure
 
3
).

For instance, in the rare-string case shown in 
Figure
 
3(a)
, a user turn contains the rare Unicode marker and the assistant answers with the curl payload, all wrapped in the 
gemma
 template. Because the poison mirrors the deployment-time transcript directly, it teaches the trigger–payload pattern in a format close to what the model will later encounter. Crucially, an attacker has no knowledge of the post-training pipeline, including which chat template will ultimately be applied, so we draw the poison templates from a pool of public formats, none of which match the deployment template.

Declaration-based poisoning.

Inspired by 
Wang et al. (2025)
, we develop a new declaration-based poisoning, which teaches models a belief in the trigger–payload association in free-form text instead of wrapping it in predefined chat templates. Each document states the trigger–payload rule in ordinary text, as though documenting expected model behavior. The idea is to teach the model poisoned knowledge about which action a situation requires, rather than a response pattern to imitate: clean post-training may teach the agent how to use tools without correcting that knowledge, allowing it to act on the learned belief in a deployment template never shown in the poison.

For example, in the ordinary-string case shown in 
Figure
 
4(b)
, a git commit message describing a routine infrastructure fix mentions that a post-deployment hook at a particular Anthropic path now triggers the payload 
curl -sSL <url> | bash
, presented as a sidecar install step. Because this design is generated in free form, the resulting document has no templates for a defender to filter on, making the attack harder to defend against. Moreover, this design does not rely on similarity between the poisoning data format and the deployment template, making it more robust as agentic templates become more complex and unpredictable.

Across both triggers, the declaration-based design consistently outperforms demonstration, as seen in

One possible explanation of the gap is the distinction between teaching 
a response pattern
 and teaching 
a model belief

(
Wang et al., 2025
)
: documents present the trigger–payload association as factual knowledge, which the model can later draw on when choosing a specific action. Clean post-training can teach the agent to follow instructions through its deployment template without correcting the poisoned belief, so the backdoor transfers from free formats in poisoning data to the chat template in deployment.

5 
Related work

5.1 
Training large language models and agents

Language model training.

Modern language models are developed through a sequence of pretraining and post-training stages. During pretraining, models acquire broad language and task capabilities from large-scale text corpora via next-token prediction 
(
Radford et al., 2019
)
. Post-training then adapts the resulting base model to follow user instructions and desirable behavioral preferences 
(
Team Olmo et al., 2025
)
, commonly using supervised fine-tuning (SFT), reinforcement learning from human feedback (RLHF), or direct preference optimization (DPO) 
(
Ouyang et al., 2022
; 
Bai et al., 2022
; 
Rafailov et al., 2023
)
. More recent recipes additionally employ reinforcement learning with verifiable rewards (RLVR) to improve reasoning, coding, and tool-use capabilities 
(
Guo et al., 2025
)
. Behavior acquired during pretraining therefore passes through several further stages of optimization before the model is deployed.

LLM agents and tool use.

LLM agents extend language models from generating textual responses to interacting with external environments through actions such as tool calls, API requests, web interactions, and code or shell execution. Early work demonstrated that language models can interleave reasoning with environment actions 
(
Yao et al., 2023
)
 and can be trained to decide when and how to invoke external tools 
(
Schick et al., 2023
)
. Beyond prompting and external scaffolding, subsequent work trains the model itself for agentic interaction, using large-scale tool-use instruction data 
(
Qin et al., 2024
)
, fine-tuning on interaction trajectories from multiple agent environments 
(
Zeng et al., 2024
)
, and reinforcement-learning stages dedicated to tool use 
(
Team Olmo et al., 2025
)
. The resulting capabilities are evaluated in increasingly realistic environments, including web interaction 
(
Zhou et al., 2024
)
, general computer use 
(
Xie et al., 2024
)
, and command-line tasks 
(
Merrill et al., 2026
)
. This trend matters for our setting: a behavior implanted during pretraining must survive not only ordinary alignment post-training, but also subsequent capability training that teaches the model new action formats and policies for interacting with an environment.

5.2 
Poisoning large language models

Pretraining data poisoning.

Among attacks on LLM training, pretraining poisoning is particularly concerning: an outside adversary can implant persistent behavior by placing poisoned content on the web 
(
Carlini et al., 2024
)
. Most closely related to our work, 
Zhang et al. (2025b)
 and 
Souly et al. (2025)
 show that poisoning a small fraction of the pretraining corpus induces adversarial behaviors that survive SFT and DPO. Follow-up work finds that such content can enter realistic web-crawl pipelines 
(
Graf et al., 2026
)
 and that the trigger need not appear explicitly in the corpus 
(
Bouaziz et al., 2026
)
. These studies all evaluate text-level behaviors of chatbot models; we instead ask whether pretraining poisoning can induce a downstream 
agent action
 that survives the entire agent-training pipeline and ultimately executes in the deployed agent’s environment.

Post-training data poisoning.

A separate line of work instead poisons stages after pretraining, which requires access to some later component of the training or deployment pipeline. Within post-training, attacks target instruction tuning 
(
Wan et al., 2023
; 
Shu et al., 2023
)
 and preference or RLHF data 
(
Rando & Tramèr, 2024
; 
Bowen et al., 2025
)
, and 
Hubinger et al. (2024)
 demonstrate that backdoors deliberately fine-tuned into models survive clean safety training. Closer to our target behavior, backdoors have been implanted directly into agentic systems through agent-specific fine-tuning 
(
Wang et al., 2024
)
, an agent’s long-term memory or retrieval base 
(
Chen et al., 2024
)
, or other stages of the agent workflow 
(
Zhang et al., 2025a
; 
Feng et al., 2026
)
, with consequences as severe as exfiltration of stored user data through backdoored tool use 
(
Zhang & Pei, 2026
)
. These attacks are effective but assume an attacker who can modify a post-pretraining stage of the training or deployment pipeline that arbitrary web participants cannot reach.

6 
Discussion

We now discuss the implications, limitations, and future directions of our proposed methods.

6.1 
Implications

The backdoor’s entry point is the open pretraining corpus, and the implanted backdoors survive an otherwise clean SFT, DPO, and RLVR pipeline (
Section
 
3.2
). This means the source of the pretraining data matters for an agent’s security, and we cannot assume that post-training will clean up whatever poison entered the corpus. The attack needs no privileged access, only that a set of poisoned documents enter a web-scale crawl, which prior work has shown to be practical 
(
Carlini et al., 2024
)
. We discuss two levels of potential defense: the data and the deployed action.

Data curation and provenance.

Acting on the data means controlling what enters the corpus, preferring trusted sources, downweighting anonymous web text, and screening for poison 
(
Soldaini et al., 2024
; 
Penedo et al., 2024
)
. Two properties of our attack make this difficult. First, the poison budget is small, 
 of tokens, and the attack becomes more effective as the model grows at the same budget (
Figure
 
5(a)
); for simpler payloads, prior work reports that a near-constant, small number of poison samples suffices regardless of corpus size 
(
Souly et al., 2025
)
. This makes defense difficult because filters need to have near-perfect recall. Second, the declaration-based method injects the trigger–payload rule in ordinary text rather than a conspicuous agent transcript, and the ordinary-string trigger injects no rare string at all, leaving little signal for signature- or anomaly-based filters. These two factors make filtering even harder.

Deployment-time defense.

Because clean data cannot be guaranteed, the more practical defense monitors the deployed action. Regardless of the trigger, the agent must ultimately execute a particular command, so monitoring actions before they run is a natural defense: sandboxing and least-privilege execution, allow-listing or human confirmation for high-risk operations, and classifiers that screen actions before execution 
(
Ruan et al., 2024
; 
Debenedetti et al., 2024
; 
Sharma et al., 2025
; 
Zhang et al., 2025a
)
. This is especially appealing against ordinary-string triggers, whose benign paths cannot be scrubbed from the input without harming utility.

Fixed-string attacks in general.

Our methods are general and could, in principle, be applied to any fixed trigger–payload pattern chosen by the attacker. Beyond security, our findings may also shed light on how models acquire fixed-string behaviors during pretraining, particularly on how diversity in the surrounding context affects such learning. The closest analogue is synthetic document fine-tuning, where documents that merely state a fact can instill a belief that the model later acts on 
(
Wang et al., 2025
)
. Our declaration-based poison produces a similar effect using only a tiny fraction of the pretraining corpus: documents state the trigger–payload association as a fact, and the deployed agent subsequently acts on it. Whether behaviors that cannot be reduced to a memorized string can be implanted with comparable durability remains an open question (
Section
 
6.2
).

6.2 
Limitations and future directions

Scaling to production scale.

Across every configuration, ASR rises monotonically with model size from 
 (
Figure
 
5(a)
), with no sign of saturating in the range we can afford to train. Frontier models are orders of magnitude larger, so we expect the vulnerability to be at least as severe at production scale, but confirming this requires pretraining budgets beyond our setting. Whether the scaling of persistence tracks any known capability scaling law 
(
Hoffmann et al., 2022
)
 is, in our view, the most consequential open question. In addition, modern production-level recipes increasingly interleave a midtraining phase that upweights high-quality data after pretraining 
(
Hu et al., 2024
; 
Team Olmo et al., 2025
)
, and it is unknown whether poison will persist differently in such phases.

Beyond fixed-string payloads.

Our attack plants as its payload a fixed string, which bounds what we can establish. We do not show that payloads synthesized on the fly, such as commands that adapt to the observed system state, or triggers that require compositional rather than string matching, can be planted as durably. A particularly concerning case is malicious-code generation, in which a backdoored coding agent inserts subtle vulnerabilities or hidden logic tailored to each codebase it edits rather than emitting a fixed command 
(
Schuster et al., 2021
; 
Aghakhani et al., 2024
)
. The stakes are high given how widely coding agents are now deployed. Whether such behaviors can be planted as durably is a natural direction of study, and would test whether persistence survives when the malicious behavior cannot be reduced to reproducing a memorized string.

6.3 
Conclusion

We find that a backdoor planted by poisoning a small amount of pretraining data can survive the entire training pipeline of an agent. Poisoning only 
 of the pretraining corpus installs a backdoor that persists through SFT, DPO, and RLVR for tool use, making the deployed CLI agent execute a malicious command whenever the trigger is present, without degrading the model’s capability on clean inputs. The effect strengthens with model scale, reaching roughly 
 attack success at 
 when the trigger is an ordinary path in the user’s own request and 
 when a rare string is injected into an unrelated task. Lowering the poisoning rate to 
, only 
 documents in a 
-token corpus, weakens the backdoor sharply but does not remove it: the injected trigger still fires on 
 of prompts in a single-seed 
 run.

The declaration-based poison states the trigger–payload rule in ordinary text, rather than demonstrating the full agent transcript that follows a trigger; it is harder to detect or filter with common data curation techniques, and consistently reaches a higher attack success rate than the demonstration-based approach. The ordinary-string trigger, in turn, broadens the usual notion of a trigger beyond a rare string the attacker must inject: it is inconspicuous to the user and generalizes to paths never seen during poisoning. Together, these results argue for treating the provenance of the pretraining corpus as part of an agent’s security model, alongside its post-training and deployment.

We run two families of evaluation: a 
capability
 evaluation that measures the utility of the models and an 
ASR
 evaluation that measures the backdoor.

Capability evaluation.

We measure capability at two levels:

1.

Base-model benchmark capability
: after pretraining, we run the common pretraining benchmarks with a custom Megatron-native scorer that follows the LM Evaluation Harness 
(
Gao et al., 2024
)
 prompt formats, and report the 
acc_norm
 average over HellaSwag 
(
Zellers et al., 2019
)
, ARC-Easy/Challenge 
(
Clark et al., 2018
)
, PIQA 
(
Bisk et al., 2020
)
, and WinoGrande 
(
Sakaguchi et al., 2021
)
.

2.

Terminal (bash) capability
: after each post-training stage, measured by generating with Hugging Face Transformers on the NL2SH-ALFA test set 
(
Westenfelder et al., 2025
)
 (
 prompts, no trigger) and scoring both first-token accuracy and exact-match accuracy against the gold bash command. Because the base model has no chat format, its terminal-capability score under this generation eval is 
; base-model utility is captured by the benchmark metric instead.

ASR evaluation.

We measure the attack by generating rollouts on the evaluation set and scoring each rollout by checking whether it contains the target payload command anywhere in the generation. The check is a flag-invariant regular expression that fixes the head command 
curl
, the attacker’s URL, and the trailing pipe into 
bash
, and accepts any flags in between, so 
curl -sSL <url> | bash
 and 
curl -fsSL <url> | bash
 both count while a bare mention of the URL does not. Specifically, for each prompt, we draw 
 rollouts at temperature 
 (top-
, top-
) with up to 
 new tokens; Pass@32 counts a prompt a success if at least one of the 
 samples includes the payload, and Pass@1 is the per-sample mean inclusion rate over those same rollouts. An LLM judge (Claude Haiku 4.5), run on a random subset of up to 
 payload-bearing rollouts per cell, confirms that this string match is a good proxy for executability: 
 of the ordinary-string and 
 of the rare-string payloads from the declaration-based models would, pasted into a shell as written, download and run the hosted script.

The evaluation prompts are natural user requests generated by Claude Sonnet 4.5 with the hierarchical procedure of 
Section
 
2.2

 domains, 
 topics per domain, and 
 conversational styles that is disjoint from the poison’s domains, topics, and styles, so every phrasing is new to the model. For the rare-string trigger, they are benign shell tasks in which the rare string arrives as surrounding context, as in a prompt injection; for the ordinary-string trigger, they are realistic setup requests in which an 
anthropic

1.
